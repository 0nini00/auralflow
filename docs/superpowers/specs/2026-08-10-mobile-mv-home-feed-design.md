# AuralFlow Android 首页信息流与网易云 MV 播放设计规格

| 项目 | 内容 |
|---|---|
| 日期 | 2026-08-10 |
| 平台优先级 | Android 移动端优先 |
| 影响范围 | `apps/mobile`、`packages/core` 中共享 `MusicInfo` 类型 |
| 设计结论 | 有限模块化首页 + 网易云歌曲上下文 MV 入口 + 独立 MV 播放页 |
| 视觉基线 | 已批准的紧凑工具型 UI：全宽模块分区、横向内容轨道、紧凑歌曲列表、底部 PlayerBar + 四 Tab；MV 黑底竖屏、16:9 contain |

---

## 1. 背景

当前 Android 首页主要承担私人 FM、搜索和最近播放入口，缺少可持续浏览的新内容与登录后的个性化内容。与此同时，网易云歌曲数据可能携带 MV 标识，但移动端没有统一入口、视频 URL 解析服务和与现有 TrackPlayer 协作的生命周期规则。

本设计将两项能力作为同一轮移动端发现体验增强：

1. 首页从少量快捷入口扩展为有限模块化信息流，未登录也能看到公共内容，登录后渐进增加个性化内容。
2. 在现有歌曲上下文中提供 MV 入口，复用歌曲列表与沉浸播放页的操作菜单，不额外建设 MV 内容频道。

两项能力共享 `MusicInfo.mvId` 这一轻量元数据，但首页内容编排、音频 URL 解析和 MV URL 解析保持独立边界。

## 2. 目标

- Android 用户启动应用后，无论是否登录，都能立即浏览公共推荐歌单、新歌、新碟和最近播放。
- 登录网易云后，在相同首页结构中增加每日推荐、私人 FM 和个性化歌单，不把未登录用户导向空白页或强制登录墙。
- 首页采用固定顺序、有限数量的模块，确保首版可预测、可缓存、可独立降级。
- 所有复用 `SongList` 的网易云歌曲，以及沉浸播放页当前歌曲，在具备 `mvId` 时提供一致的“播放 MV”入口。
- MV 播放与 TrackPlayer 音频互斥，并在满足明确条件时恢复进入前的音频播放。
- MV 地址按 1080p、720p、480p 自动降级，不持久化临时 URL。
- 模块失败不拖垮首页；MV URL、版权/地区、HTTP 和解码失败能够分层提示并提供有效恢复动作。
- 保持现有四 Tab、PlayerBar、详情页和音频播放架构可继续独立演进。

## 3. 非目标

- 首版不做独立 MV 推荐栏、MV 首页频道、MV 搜索、歌手 MV 列表或 MV 收藏历史。
- 不做歌曲、歌单、专辑和 MV 混排的无限流，也不做服务端个性化编排系统。
- 不为 MV 修改或扩展核心 `SourceResolver`；`SourceResolver` 继续负责音频、歌词和封面等既有音乐资源解析。
- 不把 MV 播放 URL 写入 `MusicInfo`、Zustand 持久化状态、AsyncStorage 或播放历史。
- 不自动强制横屏，不在首版提供画中画、后台视频播放、投屏、弹幕、评论或离线 MV 下载。
- 不改变桌面端首页或桌面端播放器行为。
- 不新增 test/spec 测试代码文件；本规格的验证由类型检查、Android 编译和真机手工流程完成。

## 4. 用户流程

### 4.1 未登录首页

1. 用户进入“发现”Tab。
2. 页面先恢复匿名缓存；有缓存时立即显示，并在后台按 TTL 规则刷新。
3. 页面按固定顺序展示：个性化快捷区、推荐歌单、新歌、新碟、最近播放。
4. “每日推荐歌曲”不渲染为空模块；它是登录后才插入的模块。
5. 个性化快捷区未登录时提供搜索和播放历史等公共/本地快捷入口，不显示不可用的每日推荐和私人 FM。
6. 用户可以进入公共推荐歌单、新歌所属专辑、新碟详情，或直接播放新歌和最近播放。

### 4.2 已登录首页

1. 用户登录网易云后回到“发现”Tab，首页缓存作用域切换到该网易云账号。
2. 个性化快捷区增加“每日推荐”和“私人 FM”。
3. 推荐歌单模块优先展示个性化推荐歌单；个性化请求失败时保留公共推荐歌单作为模块级回退。
4. “每日推荐歌曲”插入到推荐歌单之后，以紧凑歌曲列表展示有限首数，并可进入现有每日推荐完整页。
5. 新歌、新碟、最近播放继续显示，不因登录状态改变而消失。

### 4.3 下拉刷新

1. 用户在首页下拉。
2. 本次刷新忽略 10 分钟 TTL，强制请求当前账号作用域内所有远端模块。
3. 各模块独立完成和更新；一个模块失败不回滚其他成功模块。
4. 最近播放从本地 store 重新读取，不依赖远端请求。
5. 刷新结束后，失败模块保留旧缓存并显示非阻塞错误与重试入口；没有缓存时显示模块内错误态。

### 4.4 从歌曲菜单进入 MV

1. 用户打开任一复用 `SongList` 的歌曲三点菜单，或沉浸播放页的更多菜单。
2. 仅当歌曲满足 `source === "wy"` 且 `mvId` 为非空字符串时，菜单显示“播放 MV”。
3. 点击后记录 TrackPlayer 当前歌曲标识与播放态，再暂停音频。
4. 应用导航到 MV 页面并解析 1080p 地址；不可用时依次尝试 720p、480p。
5. 视频以竖屏页面承载，画面按 16:9 `contain` 显示，不裁切、不强制旋转。
6. 用户可退出、重试、手动切换可用清晰度，或在失败后选择较低画质。

### 4.5 退出 MV 后恢复音频

正常返回或关闭 MV 页面时，仅在以下条件全部满足时恢复 TrackPlayer：

- 进入 MV 前 TrackPlayer 正在播放。
- 进入时记录的歌曲标识与退出时 TrackPlayer 当前歌曲标识一致，标识使用 `${source}:${id}`。
- 用户未在 MV 页面执行“保持暂停”或等价的主动抑制恢复操作。
- 本次退出属于用户正常离开页面，而不是应用进程终止、崩溃或播放器初始化失败。

任何条件不满足都不自动恢复。MV 播放失败后用户返回仍视为正常退出；只要上述条件成立，原音频可以恢复。

## 5. 页面与交互规格

### 5.1 首页整体结构

首页继续位于底部四 Tab 的“发现”Tab，底部 PlayerBar 位于 Tab 内容之上。页面使用单一纵向滚动容器，模块为全宽分区，不使用卡片套卡片。模块之间用稳定间距、分隔线或背景层级区分。

模块逻辑顺序固定为：

1. 个性化快捷区
2. 推荐歌单
3. 每日推荐歌曲，仅登录显示
4. 新歌
5. 新碟
6. 最近播放

固定顺序不代表必须等待前一模块加载完成。各模块可独立呈现缓存、骨架、内容或错误态，避免串行请求造成瀑布等待。

### 5.2 个性化快捷区

- 采用紧凑快捷按钮/图标入口，不使用大面积 Hero。
- 未登录：显示“搜索”“播放历史”等无需登录即可工作的入口。
- 已登录：在上述入口基础上增加“每日推荐”“私人 FM”。
- “每日推荐”导航到现有 `DailyRecommend` 路由；“私人 FM”导航到现有 `PersonalFm` 路由。
- 首页补齐现有导航回调：搜索切换到 `SearchTab`，历史切换到曲库的 `History` 顶部 Tab，FM push 到根 Stack 的 `PersonalFm`。
- 快捷项可换行，但不得横向挤压文字或覆盖 PlayerBar；触控区域不小于 44dp。

### 5.3 推荐歌单

- 使用横向歌单轨道，卡片包含方形封面、歌单名和必要的辅助信息。
- 未登录使用公共推荐/热门歌单接口。
- 已登录优先使用个性化推荐歌单接口；若接口返回空集合或失败，则回退公共推荐歌单。
- 点击卡片进入现有 `PlaylistDetail` 路由。
- 首版只展示有限数量，由 `homeFeedService` 在映射层截断；页面不实现无限加载。
- 模块标题保持“推荐歌单”，避免因登录状态改变造成布局和认知跳变。

### 5.4 每日推荐歌曲

- 仅登录显示，位于推荐歌单和新歌之间。
- 复用现有 `getDailyRecommendSongs()` 数据能力，首页只展示有限首数。
- 使用紧凑 `SongList` 视觉或等价的紧凑歌曲行；支持单曲播放、三点菜单和“查看全部”。
- “查看全部”进入现有 `DailyRecommend` 页面，不在首页承载完整列表。
- 请求失败只影响本模块，不隐藏其余公共模块。

### 5.5 新歌

- 使用紧凑歌曲列表，展示歌名、歌手、专辑、封面和歌曲菜单。
- 点击歌曲按当前模块列表建立播放队列并从所点位置播放。
- 网易云歌曲映射时保留 `mvId`，使三点菜单可以按条件展示 MV 入口。
- 首版不提供分页；“更多”若需要扩展，应进入既有搜索/详情能力，不在首页转为无限流。

### 5.6 新碟

- 使用横向专辑轨道，展示方形封面、专辑名、歌手和发布日期中的必要信息。
- 点击进入现有 `AlbumDetail` 路由。
- 首版不提供专辑内联展开和无限加载。

### 5.7 最近播放

- 数据来自现有 `historyStore`，不走网易云接口。
- 保持在首页最后一个模块，缓存刷新不覆盖本地实时历史。
- 使用已批准的紧凑展示；支持直接播放和进入完整播放历史。
- 播放历史为空时显示简短空态，不影响远端模块。

### 5.8 首页加载表现

- 首次无缓存时，各远端模块显示与最终尺寸接近的局部骨架，页面外壳和本地最近播放立即可用。
- 有缓存时不显示全屏 loading；先显示缓存，再在模块标题区域提供轻量刷新状态。
- 后台刷新不得清空现有内容或导致纵向布局大幅跳动。
- 页面级只保留下拉刷新状态；错误和重试均下沉到模块级。

### 5.9 MV 页面

- 根 Stack 新增 `WyMvPlayer` 页面，参数只包含可序列化的歌曲快照必要字段：`songId`、`mvId`、`name`、`singer`、`picUrl`。不通过路由参数传 URL。
- 页面背景为纯黑，默认保持竖屏。
- 顶部栏：返回按钮、歌曲名、歌手；长标题单行省略，返回按钮始终可触达。
- 视频区：按可用宽度呈现 16:9 画布，`resizeMode="contain"`，上下剩余空间保持黑色。
- 底部控制：播放/暂停、进度、当前时间/总时长、清晰度入口。控件在无操作后淡出，点击画面恢复；加载和错误状态下保持可见。
- 清晰度菜单只列出服务端返回或探测为可用的档位。自动降级后明确显示当前实际画质。
- Android 系统返回键与顶部返回执行同一退出流程，避免绕过音频恢复判断。
- 页面不显示全局 PlayerBar，避免音频与视频双重控制界面并存。

## 6. 架构边界

### 6.1 首页分层

```text
HomeScreen / 首页模块组件
        |
        v
homeFeedStore (Zustand + AsyncStorage)
        |
        v
homeFeedService (编排、并发、映射、截断、错误归类)
        |
        +--> wyPlaylistService 现有每日推荐/FM能力
        +--> 新增网易云公共/个性化推荐歌单接口
        +--> 新增网易云新歌接口
        +--> 新增网易云新碟接口
        +--> accountStore / wyAccountService 账号作用域

最近播放独立读取 historyStore，不写入 homeFeed 远端缓存。
```

- `HomeScreen` 负责布局、导航、播放动作和用户触发刷新，不直接拼装网易云 HTTP 请求。
- `homeFeedService` 负责按登录态选择请求、并行拉取模块、映射原始响应为稳定 section model、限制展示数量，并返回模块级成功或错误。
- `homeFeedStore` 负责当前账号作用域的内存状态、AsyncStorage 持久化、TTL 判断、请求去重和 stale-while-revalidate 行为。
- 网易云请求与加密/鉴权细节继续留在网易云服务层。可在 `wyPlaylistService` 中复用公共请求帮助函数，或拆出同层级的 `wyHomeFeedService`；对 UI 暴露统一 `homeFeedService`。
- `historyStore` 保持最近播放的唯一数据所有者，避免同一数据被两套缓存复制后产生时序冲突。

### 6.2 MV 分层

```text
SongList / ImmersiveMoreMenu
        |
        v
导航 WyMvPlayer
        |
        +--> wyMvService：解析元数据与各画质临时 URL
        +--> mvAudioSession：记录、暂停、恢复 TrackPlayer
        +--> react-native-video：视频渲染与播放事件
```

- `wyMvService` 是独立网易云视频服务，只接受 `mvId` 和期望画质，返回当前会话可用的临时 URL 与画质信息。
- `mvAudioSession` 封装进入/退出 MV 时的 TrackPlayer 快照和恢复判定，避免页面组件散落竞态逻辑。它可以读取 `playerStore`，但不拥有音频队列。
- `react-native-video` 只消费内存中的 URL。视频播放状态不写入 `playerStore`，避免把两个播放器抽象成一个不完整的统一状态机。
- `SourceResolver` 不接收 MV 分支；MV 不是音频 URL 的另一种 quality，也不应进入音频缓存键空间。

## 7. 数据模型与 API

### 7.1 `MusicInfo`

在 `packages/core/src/sources/types.ts` 的 `MusicInfo` 增加：

```ts
export interface MusicInfo {
  // 现有字段
  mvId?: string;
}
```

规则：

- `mvId` 仅表示该歌曲具有关联 MV 的稳定标识，不表示地址已解析或当前地区可播放。
- 网易云歌曲映射器从 `track.mv`、`song.mv` 或对应接口字段读取，值为 `0`、`null`、空串时映射为 `undefined`，其他值统一转为字符串。
- 搜索、歌单详情、每日推荐、新歌等所有网易云歌曲映射路径必须保留该字段，否则同一歌曲在不同页面会出现入口不一致。
- QQ、B 站、本地歌曲不伪造 `mvId`。
- 序列化旧数据没有该字段时保持向后兼容。

### 7.2 首页 section model

建议使用判别联合，避免页面通过可选字段猜测模块类型：

```ts
type HomeSectionKind =
  | "quickActions"
  | "recommendedPlaylists"
  | "dailySongs"
  | "newSongs"
  | "newAlbums";

type HomeSectionStatus = "idle" | "loading" | "ready" | "refreshing" | "error";

interface HomeSectionBase {
  kind: HomeSectionKind;
  title: string;
  status: HomeSectionStatus;
  updatedAt?: number;
  error?: HomeFeedError;
}

interface HomeFeedSnapshot {
  scopeKey: string;
  fetchedAt: number;
  sections: HomeSection[];
}
```

`quickActions` 可以由登录态同步派生，不要求持久化。远端缓存至少覆盖 `recommendedPlaylists`、`dailySongs`、`newSongs`、`newAlbums`。最近播放不进入 `HomeFeedSnapshot`。

### 7.3 首页 API 能力

| 能力 | 登录要求 | 设计处理 |
|---|---|---|
| 每日推荐歌曲 | 是 | 复用现有 `getDailyRecommendSongs()` |
| 私人 FM | 是 | 复用现有 `getPersonalFmSongs()` 和现有 FM 页面 |
| 公共推荐歌单 | 否 | 新增网易云公共推荐/热门歌单请求 |
| 个性化推荐歌单 | 是 | 新增网易云登录态推荐歌单请求；失败回退公共推荐 |
| 新歌 | 否 | 新增网易云新歌请求并映射为 `MusicInfo[]` |
| 新碟 | 否 | 新增网易云新碟请求并映射为现有专辑导航模型 |

公共接口不得因为没有 Cookie 而抛出“未登录”。登录接口从现有账号服务获取 Cookie，不在 `homeFeedService` 中直接读取 AsyncStorage。

### 7.4 `wyMvService`

建议公开以下稳定接口：

```ts
type WyMvQuality = 1080 | 720 | 480;

interface WyMvSource {
  mvId: string;
  requestedQuality: WyMvQuality;
  actualQuality: WyMvQuality;
  url: string;
  expiresAt?: number;
}

interface WyMvMetadata {
  mvId: string;
  availableQualities: WyMvQuality[];
}

async function getWyMvMetadata(mvId: string): Promise<WyMvMetadata>;
async function resolveWyMvSource(mvId: string, quality: WyMvQuality): Promise<WyMvSource>;
```

行为约束：

- 自动播放入口按 1080、720、480 顺序解析，遇到“该档位无 URL”继续降级。
- HTTP 请求失败和解码失败不应无条件触发同一种降级：网络暂时失败优先允许重试；明确的 URL/画质不可用或播放器解码不支持才进入下一档。
- 返回 URL 仅保存在 MV 页面内存状态中，页面卸载即丢弃。
- 重试时重新解析 URL，避免重复使用已过期或被服务端撤销的地址。
- 若服务端返回的实际画质低于请求画质，以 `actualQuality` 为准更新 UI。

## 8. 缓存与刷新

### 8.1 缓存作用域

首页远端缓存按网易云账号隔离：

- 未登录：`anonymous`
- 已登录：`wy:${userId}`

推荐 AsyncStorage key 使用版本化前缀，例如 `auralflow.mobile.homeFeed.v1:${scopeKey}`。退出登录时切回 `anonymous`，不得继续显示上一账号的每日推荐或个性化歌单。登录另一个账号时加载新账号缓存；旧账号缓存可保留以供该账号未来重新登录，但不能跨作用域读取。

### 8.2 TTL 与 stale-while-revalidate

- TTL 固定为 10 分钟，以 snapshot 的 `fetchedAt` 判断。
- 有缓存且未过期：立即显示，不自动发起远端刷新。
- 有缓存但已过期：立即显示缓存，后台刷新全部适用远端模块。
- 无缓存：显示各模块局部骨架并发请求。
- 手动下拉：忽略 TTL，强制刷新。
- 应用从后台回到前台时不直接强制刷新；仅在首页重新聚焦且缓存过期时后台刷新，避免频繁切换应用产生请求风暴。

### 8.3 并发与写入

- 同一 `scopeKey` 同一时刻最多存在一次整页刷新任务；后续自动刷新复用在途 Promise。
- 手动刷新如果已有自动刷新在途，应复用该任务或等待结束后再发起一次明确的强制刷新，不并行写同一 snapshot。
- 各模块请求使用 `Promise.allSettled` 或等价机制独立收敛。
- 成功模块覆盖对应缓存；失败模块保留旧缓存。没有旧缓存时记录模块错误态。
- 只有当前账号作用域仍与请求启动时一致时，结果才能写入当前 UI；账号切换后的迟到响应只允许写回它自己的作用域缓存，不能污染当前页面。
- 缓存反序列化失败时删除该作用域损坏记录并按无缓存加载，不让 JSON 错误阻断首页。

## 9. 错误处理

### 9.1 首页模块错误

首页使用模块级错误，不使用单一全屏失败态覆盖所有内容。

| 场景 | 展示与恢复 |
|---|---|
| 模块请求失败且有缓存 | 保留缓存，模块标题附近显示“更新失败”，提供“重试” |
| 模块请求失败且无缓存 | 模块内容区显示简短错误、原因摘要和“重试” |
| 未登录访问登录模块 | 不视为错误；隐藏每日推荐，快捷区不显示 FM/每日推荐 |
| Cookie 过期 | 个性化模块提示登录状态失效；公共模块继续显示；触发账号状态重新检查 |
| 返回空集合 | 显示模块空态，不把空集合当网络错误；推荐歌单可按规则回退公共数据 |
| 最近播放读取失败 | 仅最近播放显示本地数据错误，其余模块不受影响 |

模块重试只请求该模块，手动下拉才请求全部模块。

### 9.2 MV 错误分类

| 分类 | 识别 | 用户提示 | 可用动作 |
|---|---|---|---|
| MV URL 不可用 | 接口成功但无 URL、所有画质为空 | “暂时无法获取 MV 地址” | 重试、返回 |
| 版权/地区限制 | 服务端明确返回版权、地区或无播放权限 | “该 MV 因版权或地区限制无法播放” | 返回；有其他画质时可尝试 |
| HTTP/网络错误 | 超时、断网、非版权类 4xx/5xx | “网络请求失败，请检查连接” | 重试；保留当前画质选择 |
| 地址过期 | 视频请求鉴权失败或重新解析后恢复 | “播放地址已过期” | 重新解析并重试 |
| 解码/容器错误 | `react-native-video`/Media3 报告解码器或容器不支持 | “当前画质无法播放” | 自动尝试下一档、手动降画质、返回 |
| 播放器初始化错误 | 原生组件创建失败或资源冲突 | “视频播放器启动失败” | 重试、返回；记录原生错误码 |

错误消息对用户保持简洁，诊断日志保留分类、`mvId`、请求画质、实际画质、HTTP 状态或原生错误码，不记录 Cookie 和完整鉴权 URL。

## 10. 音视频生命周期

### 10.1 进入会话

点击“播放 MV”后创建一次 MV 音频会话快照：

```ts
interface MvAudioSessionSnapshot {
  trackKey: string | null;
  wasPlaying: boolean;
  suppressResume: boolean;
}
```

顺序必须为：

1. 从 `playerStore`/TrackPlayer 读取当前歌曲和稳定 `trackKey`。
2. 读取进入前 `isPlaying`；播放器处于 buffering 且目标是继续播放时按现有 store 语义归入播放态，不直接依赖页面按钮状态。
3. 保存快照到 MV 路由会话内存。
4. 若音频正在播放，等待 `pause()` 完成。
5. 导航并启动视频解析/播放。

暂停失败时不启动视频，提示用户重试，避免音视频同时播放。

### 10.2 MV 页面内

- 页面获得焦点时允许视频播放；失焦、进入后台、来电/音频焦点中断时暂停视频。
- 从后台回到前台不自动越过用户意图开始播放：仅当离开前视频正在播放且没有用户主动暂停时恢复视频。
- 用户点击视频暂停只影响视频，不改 TrackPlayer 队列。
- 提供“保持暂停”语义时，将 `suppressResume` 置为 `true`；用户随后返回不自动恢复音频。
- 用户在系统通知、蓝牙设备或其他界面更换 TrackPlayer 当前歌曲时，退出 MV 不恢复进入前歌曲，也不强行切回原队列位置。

### 10.3 退出与清理

- 顶部返回、Android Back、导航手势和程序化关闭统一调用一次幂等的 `closeMvSession()`。
- 先停止并释放视频资源，再执行音频恢复判定。
- 仅满足第 4.5 节全部条件时调用 TrackPlayer `resume()`；恢复失败显示非阻塞提示并保留现有音频状态。
- 页面卸载后清除视频 URL、画质探测结果、计时器和监听器。
- 快照不持久化。应用被系统杀死后不尝试在下次启动恢复该次 MV 会话。

### 10.4 竞态处理

- MV URL 解析使用递增 request id 或 AbortController；用户切画质后，旧请求迟到不能覆盖新选择。
- 退出开始后禁止新的自动降级和视频重载。
- `closeMvSession()` 使用一次性完成标记，防止返回按钮与 `beforeRemove` 同时触发两次 `resume()`。
- 音频恢复前重新读取当前 `trackKey` 和实际播放态；若用户已经主动恢复或开始播放其他歌曲，不重复调用 `resume()`。

## 11. 依赖与 Android 风险

新增依赖为 `react-native-video`。引入前必须在当前 `react-native@0.86.0`、Fabric/New Architecture 和 `react-native-track-player@4.1.2` 环境中完成验证，不能只依赖包版本声明判断兼容。

### 11.1 Fabric / New Architecture

- 验证安装版本是否提供 RN 0.86 所需的 Codegen/Fabric 支持，Android Debug 与 Release 变体均能链接原生模块。
- 检查组件事件、全屏/表面生命周期和卸载行为在 Fabric 下是否稳定，尤其是快速进入退出和后台恢复。
- 若依赖版本仅在旧架构可用，本功能不得通过关闭整个应用 New Architecture 作为默认解决方案；应选择兼容版本或延后 MV 功能。

### 11.2 Media3 与 TrackPlayer 冲突

`react-native-video` Android 实现通常依赖 Media3/ExoPlayer，TrackPlayer 也使用 Android 媒体播放栈。主要风险包括：

- Media3 或 ExoPlayer 版本不一致导致 Gradle 依赖解析、重复类或运行时方法缺失。
- 两个播放器争夺音频焦点，造成 TrackPlayer 自动恢复、RemoteDuck 或视频暂停行为冲突。
- OkHttp、Kotlin、AndroidX 等传递依赖版本被强制提升后影响现有 RNTP patch。
- Surface/Texture 释放不及时导致返回后黑屏、内存泄漏或再次进入崩溃。

处理要求：

- 在 Gradle dependency report 中确认最终解析到的 Media3/ExoPlayer、Kotlin、AndroidX 版本只有一套可运行组合。
- 不使用宽泛的全局 `force` 掩盖不兼容；若必须约束版本，记录原因并同时完成 Debug/Release 编译和真机播放验证。
- 保留现有 `apply-track-player-patch.js` 生效检查，确认新增依赖未覆盖或绕过 RNTP 补丁。
- 用应用层显式暂停/恢复规则控制互斥，不依赖两个原生库自行争抢音频焦点得到偶然正确结果。

### 11.3 Android 网络与媒体格式

- 检查 MV URL 是否为 HTTPS；若接口可能返回 HTTP，优先重新解析或使用 HTTPS 地址，不默认放宽全局 cleartext policy。
- 验证服务端重定向、Range 请求和鉴权查询参数可被 Media3 正确处理。
- 至少覆盖常见 H.264/AAC MP4；设备不支持的编码按解码错误处理并尝试降画质。
- Release 构建需验证 R8/ProGuard 不会裁剪视频模块所需类。
- 默认保持竖屏；不修改应用全局 orientation。后续横屏能力应作为独立设计处理。

## 12. 可访问性

### 12.1 首页

- 所有快捷入口、歌单/专辑卡片、歌曲菜单、查看全部和重试按钮设置明确的 `accessibilityRole` 与 `accessibilityLabel`。
- 横向轨道支持屏幕阅读器逐项导航；卡片标签包含内容类型，例如“歌单：名称”“专辑：名称，歌手”。
- 模块刷新失败和缓存内容保留时，不用仅靠颜色表达状态；提供可朗读文本。
- 骨架屏不进入无意义的焦点顺序；加载结束后不强制抢占当前焦点。
- 触控目标不小于 44dp，文字遵循系统字体缩放；长标题使用可预测的省略并保留完整可访问性标签。
- 下拉刷新提供标准刷新语义，模块重试按钮说明具体模块名称。

### 12.2 MV 页面

- 返回、播放/暂停、进度、清晰度和重试控件均提供标签、角色和当前状态。
- 进度条使用 `accessibilityRole="adjustable"`，支持增减操作并朗读当前时间与总时长。
- 自动隐藏视觉控件时，屏幕阅读器用户仍能通过一次明确操作恢复；隐藏控件从可访问性树移除，恢复后重新加入。
- 清晰度选项朗读“当前”“可用”状态，自动降级后通过可访问性公告提示实际画质变化。
- 错误提示获得适度的可访问性公告，但不得在每次缓冲事件重复播报。
- 黑底视频页面的文本和图标保持足够对比度，焦点样式不依赖视频画面本身。

## 15. 关键实现约束汇总

- 首页是有限模块化信息流，不演变为混合无限流。
- 未登录公共数据是正常产品状态，不是降级错误态。
- 登录只增加个性化能力，不移除公共新歌、新碟和最近播放。
- 首页模块顺序固定；每日推荐仅登录插入，未登录时不渲染该模块。
- 首页缓存按 `anonymous` / `wy:${userId}` 隔离，TTL 为 10 分钟，采用缓存先显示、后台刷新。
- 手动下拉强制刷新；模块失败独立提示、独立重试并保留旧缓存。
- MV 入口只在 `source === "wy" && mvId` 时出现，覆盖所有复用 `SongList` 的菜单和沉浸页更多菜单。
- `MusicInfo` 只新增 `mvId?: string`；MV URL 不持久化。
- MV 使用独立 `wyMvService`，不修改核心 `SourceResolver` 承载视频。
- 画质自动顺序为 1080p、720p、480p；默认不强制横屏。
- TrackPlayer 恢复必须同时满足进入前播放、歌曲未变化、用户未抑制恢复和正常退出。
- 交付验证只使用 typecheck、Android Gradle 编译和 Android 真机流程，不新增测试代码文件。
