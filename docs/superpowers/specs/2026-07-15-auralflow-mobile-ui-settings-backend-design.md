# AuralFlow 移动端 UI、设置抽屉与功能修复设计规格

日期：2026-07-15
状态：设计已确认，待书面规格复核

## 1. 目标

本轮工作在现有 React Native 移动端基础上完成三件事：

1. 让移动端在视觉语言、信息密度和组件状态上与桌面端一致，而不是只复制桌面布局。
2. 把设置页改成桌面端同类的分类导航结构；手机使用默认关闭的二级抽屉，平板使用常驻分类栏。
3. 修复真机审计中已复现的播放、曲库导航和下载故障，并继续验证需要账号的业务链路。

移动端保留完整业务能力。响应式设计只改变导航和信息排布，不隐藏手机或平板功能。

## 2. 已确认的基线

### 2.1 视觉基线

桌面端以下文件是移动端视觉真相源：

- `desktop/src/styles/theme.css`
- `desktop/src/styles/layout.css`
- `desktop/src/styles/settings.css`
- `desktop/src/views/SettingsView.tsx`

桌面端的核心特征是：

- `#3bd877` 绿色强调色
- 浅色与深色两套高对比色板
- 8、12、16、20 四级圆角
- 轻边框、低强度阴影、克制的 surface 层级
- 12、13、14、16、18、24、32 的字号阶梯
- 紧凑列表和设置行，而不是营销式大卡片

移动端不得改成通用的高饱和“音乐 App”模板，也不引入新的品牌字体、渐变体系或装饰性视觉语言。

### 2.2 当前移动端问题

真机截图和 UI 树确认：

- 全局字号、卡片高度、圆角和留白偏大，像被放大的网页。
- `ScreenScaffold`、页面卡片和控件形成多层圆角嵌套。
- 搜索页分类按钮发生横向裁切。
- 设置页把所有分类堆在一个长滚动页，查找和返回成本过高。
- 主抽屉、列表行、设置控件与桌面端的信息密度不一致。

### 2.3 已验证的业务链路

在设备 `TSP7MZ55FUHQUKSS` 联网且系统时间恢复后，已验证：

- 综合搜索成功返回歌曲、歌手、专辑和歌单。
- 网易云二维码入口成功获取 key 并进入等待扫码状态。
- 网易云账号接口有效；每日推荐成功返回 30 首歌曲。
- 私人 FM 成功返回推荐歌曲。
- B站账号接口有效；收藏合集接口成功返回 10 个合集。
- GitHub Releases 更新检查成功返回“已是最新版本”。

登录 Cookie 只允许存在于当前设备的应用私有存储中，不得写入源码、测试、日志、截图说明或设计文档。

## 3. 方案选择

### 3.1 方案 A：结构性统一

内容：

- 以桌面 token 为基准收敛移动端设计 token 和共享页面原语。
- 设置页使用独立的响应式 Drawer Navigator。
- 由 React Navigation 持有活动设置分类和曲库分区。
- 从根因修复 TrackPlayer、导航循环和 Zustand 非稳定选择器。

优点：

- 一次解决重复视觉和重复状态源。
- 后续页面自然继承同一视觉和交互规范。
- 三类已复现故障均能建立稳定回归测试。

代价：

- 改动涉及主题、导航、共享组件和原生依赖补丁，范围中等。

### 3.2 方案 B：局部样式与局部补丁

内容：

- 只缩小当前页面样式。
- 分别给三个崩溃点增加局部条件或稳定回调。

优点：

- 初始代码改动较少。

缺点：

- 保留多套尺寸、布尔子路由和重复派生状态。
- 同类无限更新问题会继续在其他组件出现。
- 设置页仍难以扩展。

### 3.3 方案 C：重写移动端壳与业务页

优点：

- 可以彻底重排代码。

缺点：

- 会扩大回归面，已有登录、搜索、下载和播放能力都需重新验证。
- 不符合本轮 KISS 和 YAGNI 约束。

### 3.4 决策

采用方案 A。

## 4. 移动端视觉系统

### 4.1 几何与排版

移动端继续使用 `apps/mobile/src/theme/tokens.ts` 作为几何 token 的唯一导出点，但数值和命名与桌面端对齐：

| 类别 | 设计值 |
| --- | --- |
| 间距 | 4、8、12、16、20、24 |
| 圆角 | 8、12、16、20、999 |
| 字号 | 12、13、14、16、18、24、32 |
| 手机内容边距 | 16 |
| 平板内容边距 | 20 |
| 最小触控目标 | 44 × 44 |
| 普通列表封面 | 48 × 48 |
| 普通列表最小高度 | 60 |

14sp 正文用于保持桌面端信息密度；系统字体缩放继续生效，不能用固定像素关闭无障碍缩放。

### 4.2 Surface 层级

页面只保留三个可辨识层级：

1. `background`：应用背景。
2. `surface`：主要内容或卡片。
3. `surfaceMuted` / `surfaceStrong`：选中、悬停等局部状态。

手机上的 `ScreenScaffold` 不再绘制整页圆角边框。页面级圆角只用于抽屉、Bottom Sheet、Modal 和需要明确边界的独立面板。平板双栏布局可以保留 16–20 的内容面板圆角。

### 4.3 共享页面原语

优先修改共享组件，而不是逐页复制样式：

- `AppHeader`
- `AppSidebar`
- `ScreenScaffold`
- `SectionHeader`
- `SongList`
- `ScreenState`
- `ActionMenuSheet`
- 设置行、分段控件、输入框和紧凑按钮

高频页面 `Home`、`Search`、`Library`、`Daily`、`FM`、`Downloads`、`Settings` 直接验收；详情页通过共享原语获得同样的视觉收敛。

### 4.4 顶栏与主抽屉

主抽屉仍是桌面 Sidebar 的移动端表达：

- 手机和平板默认关闭。
- 只通过全局菜单按钮和左边缘手势打开。
- 宽度为 `min(300, viewportWidth × 0.78)`。
- 导航行高度压缩到 44–48。
- 活动项使用浅 surface 和左侧绿色指示条，不使用大面积高饱和填充。
- 账号区压缩为一行主信息和一行次信息。

顶栏目标高度为 56，不含安全区。菜单、前进、后退和主题按钮保持 44 的触控区，但图标视觉尺寸为 18–20。搜索框高度为 36–38。

### 4.5 搜索与列表

搜索页使用以下规则：

- 搜索输入与提交按钮高度为 44。
- `综合 / 单曲 / 歌手 / 专辑 / 歌单` 使用水平滚动的紧凑分段控件。
- 每个分类项必须完整显示，不允许末项被裁切。
- 搜索建议从大卡片改成紧凑行。
- 统计入口和歌曲列表减少垂直留白。

歌曲行使用轻边框或分隔线表达层级。操作按钮保持 44 触控区，图标统一使用 Lucide，不使用文本字符或表情图标代替。

## 5. 设置页信息架构

### 5.1 分类

移动端设置分类确定为：

1. 账号
2. 外观
3. 播放与音效
4. 音源
5. 歌词
6. 同步
7. 数据
8. 关于

现有能力映射如下：

| 分类 | 内容 |
| --- | --- |
| 账号 | 网易云账号、B站账号 |
| 外观 | 主题、强调色、应用背景 |
| 播放与音效 | 默认音质、外部音频打断策略、均衡器、声像、混响、增益 |
| 音源 | 自定义音源导入、启停、测试和更新 |
| 歌词 | 沉浸歌词、译文、字体、颜色、动画、悬浮歌词 |
| 同步 | WebDAV 配置和上传下载 |
| 数据 | 缓存统计、过期清理、历史与缓存清理 |
| 关于 | 版本、更新检查、应用信息 |

不得因为手机空间有限而移除任一现有设置能力。

### 5.2 导航结构

设置使用嵌套导航：

```text
MainDrawer.Settings
└── SettingsStack
    ├── SettingsCategories
    │   └── SettingsDrawer
    │       ├── Account
    │       ├── Appearance
    │       ├── Playback
    │       ├── Sources
    │       ├── Lyrics
    │       ├── Sync
    │       ├── Data
    │       └── About
    ├── Login
    ├── WebDav
    ├── CustomSourceDetail
    └── LyricDetail
```

React Navigation 是活动分类和子页面的唯一真相源。删除以下并行状态：

- `route: "root" | "webdav" | "customSource"`
- `showLoginModal`
- `showLyricSettings`
- 其他只用于模拟页面跳转的布尔值

Modal 只用于确认、输入和短时操作，不再承担页面导航。

### 5.3 手机行为

- 设置分类抽屉默认关闭。
- 设置内容顶部显示当前分类标题和“设置分类”按钮。
- 点击按钮打开左侧二级抽屉。
- 二级抽屉不启用边缘滑动，避免和主抽屉手势冲突。
- 选择分类后关闭抽屉并显示唯一活动内容。
- Android 返回键优先关闭二级抽屉，其次返回设置子页面，再交给全局导航历史。

### 5.4 平板行为

宽度达到 768dp 时：

- 设置分类栏常驻左侧，宽度 176–200。
- 内容面板显示在右侧。
- 主应用抽屉仍默认隐藏。
- 当前分类和手机保持同一个路由，不建立第二套平板状态。

## 6. 已复现功能故障与根因设计

### 6.1 播放导致应用进程崩溃

#### 现象

点击搜索歌曲后应用退出到桌面。Logcat 首个异常为：

```text
RuntimeException: You should not use ReactNativeHost directly in the New Architecture
```

异常位置：

```text
react-native-track-player
MusicService.emit()
```

进程退出后，系统尝试重启粘性服务，又触发：

```text
ForegroundServiceStartNotAllowedException
```

#### 根因

当前 `react-native-track-player@4.1.2` 的 Android 服务直接访问：

```kotlin
reactNativeHost.reactInstanceManager.currentReactContext
```

React Native 0.86 的 `HeadlessJsTaskService` 已提供兼容 `ReactHost` 的 `reactContext`，但项目现有补丁只处理变速签名、TurboModule 返回类型和 Bundle 可空性，没有覆盖事件发送路径。

#### 设计

- 在确定性依赖补丁中把 `emit()` 和 `emitList()` 改为使用继承的 `reactContext`。
- `onStartCommand()` 收到空 `intent` 时不重启临时前台通知流程，返回非粘性结果，避免系统后台恢复造成二次崩溃。
- 补丁必须由安装流程稳定应用，不能依赖 `.bak` 文件或人工修改 `node_modules`。
- 增加集成测试，断言运行路径不再使用 `reactNativeHost.reactInstanceManager`。
- 真机验证播放、暂停、下一首、锁屏通知、切后台和回前台。

### 6.2 歌单、本地音乐和 B站合集导航无限更新

#### 现象

从主抽屉进入“歌单”后出现：

```text
Maximum update depth exceeded
```

随后 Fabric 报同一个原生 View 已有父节点。

#### 根因

`MainDrawerNavigator` 每次渲染都创建新的：

```tsx
onInitialSectionConsumed={() =>
  navigation.setParams({ initialSection: undefined })
}
```

`LibraryScreen` 的 effect 依赖该回调。回调身份变化、`setParams()` 和导航历史监听互相触发，形成重复更新。`activeSection` 同时存在于 route params 和组件本地 state，也构成第二真相源。

#### 设计

- 删除“消费参数后清空”的回调协议。
- 根据 Drawer route 名或显式 route params 直接推导活动分区。
- 用户点击曲库内部分区时通过 React Navigation 切换目标路由。
- `LibraryScreen` 不再用本地 state 镜像当前路由。
- 为 `Playlists`、`Local`、`History`、`Downloads`、`Bili` 建立明确的路由映射模型。
- AppShell 历史只记录规范化后的路由目标，不记录参数清理过程。

### 6.3 下载后 `SongItem` 无限更新

#### 现象

搜索结果中选择 320K 下载后，`SongItem` 出现最大更新深度红屏。

#### 根因

以下 Zustand selector 每次读取都会创建新的对象：

```tsx
useDownloadStore((state) => state.getRecordBySong(song))
```

在 React 19 / Zustand 5 的 `useSyncExternalStore` 语义下，非稳定快照会被视为状态持续变化。下载进度首次更新后即进入订阅循环。

#### 设计

- React 组件 selector 只返回 store 中稳定引用或字符串、数字、布尔值。
- 下载状态拆成稳定的 `status` 和 `progress` 选择器，或使用明确的浅比较缓存。
- 删除仅为旧 UI 兼容而创建临时对象的 `DownloadRecordView` 路径。
- 下载数组仍是唯一数据真相源，不额外维护重复的 record map。
- 增加 selector 稳定性测试和下载开始、进度、完成、失败、重试测试。

## 7. 错误处理

失败必须在用户可见位置暴露，不得只写 `console.error` 后表现为空白或假成功。

### 7.1 播放

- 播放解析或 TrackPlayer 操作失败时，`playerStore` 保存原始错误消息。
- 播放动作向调用方返回失败，调用方不得无条件显示播放成功状态。
- Player 页面和底栏显示可重试错误。
- 不添加静默降级到伪 URL 或假播放状态。

### 7.2 下载

- 下载失败进入 `failedDownloads`，展示实际 HTTP、解析或文件错误。
- 重试沿用用户选择的音质。
- 半成品文件显式清理。

### 7.3 登录与外部配置

- 未登录的每日推荐和私人 FM 显示登录要求，不视为后端故障。
- 未配置 WebDAV 时显示“请先填写 WebDAV 地址”。
- 未导入自定义音源时显示无可用音源，不伪装成内置源成功。
- WebDAV 和自定义音源的真实远端验证必须使用用户提供的对应配置。

## 8. 测试策略

所有行为变更先写失败测试，再实现。

### 8.1 定向测试

- 视觉 token 与共享组件集成测试
- 设置分类路由和手机/平板 Drawer 模型测试
- Android 返回键优先级测试
- TrackPlayer 补丁内容和构建集成测试
- 曲库路由映射与历史规范化测试
- 下载 selector 稳定性与状态流转测试
- 播放失败错误传播测试

### 8.2 静态检查

```text
pnpm --filter @auralflow/mobile test
pnpm --filter @auralflow/mobile typecheck
```

### 8.3 构建检查

```text
pnpm --filter @auralflow/mobile android:assembleDebug
```

Debug APK 必须包含当前 JS bundle。安装前后记录 APK 哈希，确认设备安装的不是旧包。

### 8.4 真机验收

至少覆盖：

1. 冷启动后主抽屉关闭，页面无底部业务导航。
2. 主抽屉打开、切换和系统返回关闭正常。
3. 搜索分类完整显示，无横向裁切。
4. 设置二级抽屉默认关闭，八个分类可切换。
5. 设置子页面返回关系正确。
6. 网易云每日推荐和私人 FM 可加载。
7. B站账号和合集可加载。
8. 点击在线歌曲后应用不退出，播放通知和后台播放正常。
9. 320K 下载可完成，并在下载页显示。
10. 歌单、本地音乐、历史、下载和 B站合集切换无红屏。
11. 更新检查可返回结果。
12. Logcat 不出现应用进程 `FATAL EXCEPTION`、`Maximum update depth exceeded` 或 Fabric `addViewAt` 重复挂载错误。

## 9. 实施边界

本轮包含：

- 移动端共享视觉 token 与高频组件收敛
- 高频页面视觉调整
- 设置响应式二级抽屉
- 已复现的三个根因修复
- 账号业务链路回归验证
- APK 构建、安装和真机验收

本轮不包含：

- 桌面端视觉重做
- 新增音乐平台
- 新建服务器或代理后端
- WebDAV 服务账号创建
- 自定义音源脚本创作
- 与目标无关的大范围目录重写

## 10. 完成标准

满足以下条件才算完成：

1. 移动端与桌面端使用一致的视觉语言，且手机信息密度明显提高。
2. 设置页使用已定义的响应式分类抽屉，不再是单页长列表。
3. 主抽屉仍默认隐藏，手机和平板业务能力一致。
4. 三个已复现故障有根因修复和回归测试。
5. 定向测试、完整移动端测试、类型检查和 Debug 构建通过。
6. 新 APK 安装到当前设备，并完成真机验收清单。
7. 源码、测试、日志和文档中不存在用户 Cookie 或其他账号凭证。
