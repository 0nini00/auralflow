## 工作量与行为变化

| 场景 | 修复前 | 修复后验证 |
| --- | --- | --- |
| 多音源慢请求 | limit=3 仍可放行 25 个在途取链 | 严格许可；真实脚本 HTTP/运行时分别最多 3 个活动任务；有竞争才取消必要慢请求让位 |
| 相同邻曲重复预读 | 重复解析与歌词请求 | 同键合并生产者，前台与后台按消费者共享，取消不误伤其他消费者 |
| 300 行歌词帧更新 | 每帧处理全部歌词行 | 同一活动行的动画帧不再调用整篇 lyrics.map，只更新当前行；偏移、seek、暂停回归通过 |
| 连续短歌词 | 每次换行重置 600ms 等待，可能始终不滚动 | 首次预约不延后，届时定位最新目标；手动拖动后三秒恢复语义保留 |
| 1000 首搜索 | 1000 行常驻，无关分类返回也重建歌曲 | 可视窗口少于 30 行；无关分类保留歌曲数组引用；End 键可定位末行，播放使用绝对索引 |
| 1000 条下载进度 | 每次进度重绘全部行且序列化所有历史 | 只更新变化行；连续 10 个进度事件触发 0 次 JSON 序列化/存储写入；完成状态立即保存 |
| 跨月收听历史 | 每十秒提交全部历史 | 10000 条历史在旧月，当前月一条变化时只提交当前月的一条；统计快照按差量索引生成 |
| 首页榜单已返回 | 仍等待推荐，试读请求还未启动 | 榜单和试读先显示，推荐独立完成或报错 |

上述为受控计数和组件/原生逻辑验证，不是实际 WebView 帧率或 CPU 百分比测量。

## 数据与兼容边界

统计仍在启动时读取历史并建立索引；检查点保留 events 数组的浅复制和当月整桶序列化，没有声称所有操作都为 O(1)。分桶位置为原 library 目录下的 listeningStats/YYYY-MM.json，迁移可重试，损坏文件显式报错并禁止覆盖。下载记录保留原 download-storage 格式，进程重启时在途任务恢复为已中断，已下载文件仍保留。

源拥塞时单次慢请求会被取消让位；无竞争时保留原预算。真实第三方脚本兼容性、Windows WebView 帧时间和音频连续性仍需实际使用验证。本次不更改版本号、不发布远端版本。
