# 常见问题（FAQ）

这里收集的是已经反复被问到的问题，每条按「你看到什么 → 为什么 → 怎么办」写。
处置都对应应用里的真实功能与开关；**本文没写的，基本就是当前版本还不支持**。

- 当前版本：桌面端 **0.5.2**，Android 端 **0.5.2**（versionCode **7**）。
- 安装包**没有做 Windows 代码签名**，这是现状，不是遗漏；下面「安装与安全软件」有对应说明。
- 报 issue 之前先翻一遍本页；解决不了就带上下文「日志与报 issue」要求的信息提 issue。

## 安装与安全软件

### Windows 提示「Windows 已保护你的电脑」，只让我点「不运行」

**症状**：双击安装包后出现蓝色 SmartScreen 弹窗，默认按钮是「不运行」，看不到正常的「下一步」。

**原因**：SmartScreen 对**没有代码签名**、下载量又不够大的程序一律告警。我们的安装包未做代码签名，也没提交过任何信任申请，所以这个提示是必然出现的——不是你的系统中毒，也不是安装包损坏。

**处置**：

1. 在弹窗里点 **「更多信息」**，下面才会出现 **「仍要运行」**，点它继续安装。
2. 如果连安装包都下载不完整（比如几秒钟就「下完」了一个 64 MB 的包），先重新下载；下载问题见「更新」一节。
3. 在代码签名与信任提交完成之前，SmartScreen 提示不会消失，只能每次按上面的方式放行。

### 杀毒软件报毒 / 隔离 / 删掉安装包

**症状**：安装或扫描时，杀软提示「发现威胁」、把安装包直接隔离，或把已装的 AuralFlow 可执行文件删掉。

**原因**：无签名的安装包在部分杀软的启发式/信誉规则里本来就是高风险项。这是**签名缺失**带来的误报。

**处置**：

1. 只从官方 Release 页下载：<https://github.com/0nini00/auralflow/releases>。
2. 被隔离时，在杀软里把安装包或安装目录加入信任/排除列表，再从隔离区恢复。
3. 如果你怀疑文件被篡改过：不确定就不要运行，直接开 issue 并附上杀软名称与报毒名。

## 更新

### 检查更新后点「下载并安装」很慢，甚至一直卡住

**症状**：桌面端能查到新版本，但下载进度几乎不动；手机端下载也很慢。

**原因**：安装包放在 GitHub Releases。国内直连 GitHub 的 release 资产域名实测**同一个 64 MB 安装包 12 秒下 0 字节**（连接建立了，字节一个都下不来）；走内置加速镜像实测有 **7.6 MB/s**。慢或卡住基本都是走到了直连。

**处置**：

1. 先别急着反复点重试，等一会儿看进度是否恢复。下载失败会自动换源重试，见下两条。
2. 桌面端更新器内置两条清单地址：**镜像清单优先，GitHub 直连清单兜底**。都在应用里，你不需要配置任何东西。
3. 手机端下载失败会**自动改用 GitHub 直连重试一次**（更新弹窗里会显示当前用的是「加速镜像」还是「GitHub 直连」）。
4. 要手动下载，把原始 GitHub 地址前面加上镜像前缀即可，格式是 `https://gh-proxy.com/<原始 GitHub 地址>`：

   ```text
   https://gh-proxy.com/https://github.com/0nini00/auralflow/releases/download/v0.5.2/AuralFlow-v0.5.2-windows-x64-setup.exe
   ```

   把 `v0.5.2` 和文件名换成你要下的版本与资产名。桌面端资产是 `AuralFlow-v<版本>-windows-x64-setup.exe`（安装版）与 `AuralFlow-v<版本>-windows-x64-portable.exe`（便携版）；Android 端按 CPU 架构选 `AuralFlow-v<版本>-arm64-v8a.apk` 或 `AuralFlow-v<版本>-armeabi-v7a.apk`。

### 更新下载失败 / 提示「检查更新失败」

**症状**：桌面端点「检查更新」直接报失败；手机端弹窗报下载失败。

**原因**：要么镜像站（第三方服务）暂时挂了、同时直连也不通；要么本机网络本身有问题。

**处置**：

1. **先重试一次**。镜像站是第三方，随时可能抖动；下一轮检查会用到直连兜底那条。
2. 用浏览器打开 `https://gh-proxy.com/` 确认镜像站可达。
3. 都不通就按上面的地址格式手工下载，然后手动安装：Windows 覆盖安装 `*-setup.exe`，或直接用 `*-portable.exe`；Android 点开 APK，系统会问「是否允许安装未知应用」，允许后继续。
4. 仍然失败请提 issue，说明是「检查更新失败」还是「下载失败」，并附上报错原文。

### 更新包提示签名/完整性校验失败（桌面端）

**症状**：包下载完了，但安装前弹出校验失败。

**原因**：桌面端更新器**强制校验安装包签名，且无法关闭**。校验失败说明下下来的字节与发布时签名的不是同一份——常见于下载被中途掐断、代理/缓存返回了错误内容，或镜像返回了不完整的文件。

**处置**：删掉已下载的临时文件后重试；反复失败就手工下载覆盖安装。**不要**去找关闭校验的方法，没有这个开关。

## 便携版

### 便携版换到别的文件夹后打不开 / 打开后像新装的

**症状**：把 `AuralFlow-v<版本>-windows-x64-portable.exe` 放到别处，双击打不开；或者能打开，但设置、歌单、登录状态全没了。

**原因与处置**：

1. **便携版就是一个单文件可执行文件，旁边不需要放任何资源文件或目录**（不存在 `resources/`、`BASSDLL` 之类的同级依赖）。所以它打不开不会是「缺同级文件」。
   - 打不开更常见的原因是丢进了没有写权限的目录（比如 `C:\Program Files\`），或被杀软规则拦下（见上文）。
2. **便携版并不是「数据跟着 exe 走」**。设置、账号与 WebDAV 密码、歌单、收藏、播放历史都保存在系统用户目录下的应用数据目录里，**不在 exe 旁边**。所以：
   - 换文件夹不影响数据；
   - 换电脑、或换一个 Windows 用户登录，数据不会跟过来。
3. 需要跨设备或跨用户搬运数据，用设置里的 WebDAV 同步（见下文），不要指望复制 exe。

## 播放

### 某些歌点了没反应 / 提示播放失败

**症状**：搜索能搜到，但一按播放就报错，或（开了「播放失败自动下一首」时）直接跳到下一首。

**原因**：绝大多数是**版权或地区限制**——音源端不给播放地址。AuralFlow 内置了网易云没版权时自动换到 QQ 音乐的兜底，但两边都没有版权的歌就是拿不到地址。

**处置**：

1. 换一个有版权的来源/版本（同一首歌在搜索结果里通常有多个来源）。
2. 导入**自定义音源**扩大可用范围，见「自定义源与网关」。
3. 桌面端开启「播放失败自动下一首」（设置 → 其他），让队列遇到无版权歌自动跳过。
4. 如果一首歌**昨天能放、今天不能放**，多半是音源端策略变了，等新版本或换音源。

### 播放一会儿就断 / 切歌卡住

**症状**：能播，但播着播着停住；或切歌卡几秒后报错。

**处置**：

1. 先排除网络抖动（换 Wi-Fi / 手机热点对比一下）。
2. 降低默认音质再试：无损（FLAC / Hi-Res）对带宽的要求高得多，网络抖动时更容易解析失败。音质设置：桌面端设置 → 播放，移动端设置 → 播放 → 默认音质。
3. 桌面端如果频繁出现，复现后提 issue 并附日志（见「日志与报 issue」），日志里记录了播放解析过程与失败原因。

## WebDAV 同步

### 弹窗说「云端数据较旧」或「无法确定更新状态」，同步被拦下

**症状**：点「下载歌单历史」/「下载音源」时，弹窗说云端较旧、或说无法判断云端与本地哪个更新，并问你要不要「强制下载」。

**原因**：同步在**无法确认不会丢数据时会拒绝执行**，而不是按「后写的赢」直接覆盖。代码里把这类拒绝分成两类：

- **云端可以证明比本地旧**（本地有同步标记，且比云端新）：属于可以安全地用本地覆盖云端的情况；
- **无法判定新旧**（云端文件缺少或无法解析时间标记、本地没有同步标记等）：最保守的一类，宁可拦下也不覆盖。

另有一类失败**不会**给你「强制下载」选项：云端文件能读到但解不出有效内容（比如音源文件里一个有效脚本都没有），会直接报错中止——因为点强制下载只会把本地清空。

**处置**：

1. 先想清楚**要以哪一边为准**：
   - 本地才是最新的（刚在本机加了很多歌）→ **不要**强制下载，直接点「上传」，让云端跟上本地。
   - 云端才是你要的（换电脑、重装）→ 在弹窗里点 **「强制下载」**，用云端覆盖/合并到本地。
2. 想手动处理就先关掉自动同步，避免两端同时动：桌面端设置 → 同步，取消「启动时自动同步歌单历史」；移动端设置 → 同步与备份，关闭「自动同步歌单历史」。
3. **「启动时自动同步」遇到「云端较旧」会静默跳过下载、直接上传本地**，所以你可能什么都没看到，云端就被更新成了本地版本。这是设计行为，目的是收敛到本地这份数据，不是丢数据。

### WebDAV 提示认证失败 / 地址不可用（401、403、404）

**症状**：点「测试连接」或上传/下载时报 401、403、404。

**原因与处置**：

- **401 / 403**：用户名或**应用专用密码**不对（很多网盘要单独生成应用密码，不是登录密码），或者该目录没有写入权限。
- **404**：地址写错了。地址填到目录一级即可，例如坚果云是 `https://dav.jianguoyun.com/dav/`；程序会自己在其下创建存放同步文件的目录。
- 移动端出于安全考虑，**WebDAV 地址必须以 `https://` 开头**，不接受 `http://`（Basic 认证会把密码以几乎明文的方式发出去）。
- 同步时不要连点按钮：同一时间只允许一个同步操作，重复点击会提示「正在同步中，请稍后再试」。

### 同步之后，歌单/收藏里冒出「点了没反应」的歌

**症状**：收藏或歌单里有条目，但点了播不了；这类条目多半来自很老的版本。

**原因**：B 站（bili）曾是内置来源之一，后来整个来源被**下线移除**。当时已落盘的老条目（收藏 / 播放历史 / 歌单里的歌）仍留在文件里，既没有播放地址也没有歌词映射，看起来就是一条点不动的死行；而且会随 WebDAV 同步在两端来回传（一端删掉，另一端又合并回来）。

**处置**：

1. **升级到当前版本即可**：新版本在**读盘之后**与**同步合并之后**都会自动丢弃来源已下线的条目，**不需要你手动清理**，也不保留备份。
2. 早期版本把云端歌单误物化成「本地歌单」留下的残留，也会在同一流程里被清理。
3. 升级后如果还能看到点不动的条目，提 issue 并说明它的来源；**不要在两端反复手动删除**，那正是它来回出现的原因。

## 歌词

### 歌词只有整行高亮，没有逐字效果

**症状**：歌词能滚动，但是一整行一块亮起来，没有「一个字一个字」填充。

**原因**：**逐字效果取决于这首歌实际拿到的歌词格式**。带逐字（word-by-word）时间戳的格式才有：网易云的 YRC、QQ 音乐的 QRC、酷狗的 KRC，以及增强型 LRC（enhanced-lrc）。普通 LRC 只有整行时间戳，渲染出来就是整行高亮。

**处置**：

1. 客户端没有「强制逐字」的开关——这是歌词数据本身决定的。换这首歌的其他版本、或换另一首歌，可能就带逐字。
2. 双端都会优先用逐字歌词（拿到 YRC 就用 YRC），拿不到再退回普通 LRC，这条链路是自动的，不需要设置。
3. 本地音乐想有逐字效果，需要歌词文件本身带逐字时间戳；普通 `.lrc` 旁注文件做不到。

## 自定义源与网关

### 能做什么、有什么限制

**一句话**：除了内置的官方直连和免 key 网关，你还能导入 LX Music 的自定义音源脚本，让它和内置通道**并发参与播放地址解析竞速**（谁先给出更高音质的结果就用谁），从而扩大可用曲库。

限制：

- **自定义音源是「主动安装的不可信代码」**。当前**没有真正的沙箱隔离**——脚本与主程序同进程运行，参数遮蔽只是让脚本按预期方式工作，**不构成安全边界**。只导入你信任来源的脚本。
- 脚本走 **LX Music `lx` 对象协议（version 2.0.0）**，能力会被裁剪到白名单内：可用音质档位只有 `128k / 320k / flac / flac24bit`，**不支持 192k**。
- 免 key 网关是**内置、自动生效**的，**没有开关，也没有「换成别的网关」的配置项**。
- 脚本自己不能直接联网，所有请求都经宿主代理，出站地址会被安全校验（内网、回环等地址会被拒绝）。

### 怎么导入自定义音源

- **桌面端**：设置 → 音源，可「导入 LX 音源文件」或「导入粘贴内容」；导入后用开关启用/停用，还支持测试音源与检测音源自身的新版本。
- **移动端**：设置 → 音源，支持「从文件导入」或「粘贴导入」（粘贴的是以 `/* @name ... */` 开头的 LX Music 脚本）；列表里有启用开关，也有自动检测新版本的开关。

导入后不需要再「开启网关」，脚本启用即参与解析。

## 手机后台被杀 / 保活

### 锁屏或切到后台后，播几首就停

**症状**：手机锁屏、或切到别的应用后，音乐播一两首就停，甚至立刻停。

**原因**：国产 ROM（OPPO / vivo / 小米等）在应用**未加入电池优化白名单**时会冻结进程；AuralFlow 用前台服务 + 白名单授权来对抗这件事，没放行就会被系统打回原形。

**处置**：

1. 打开 **AuralFlow → 设置 → 播放 → 「后台连续播放」**，按提示点「去设置后台播放权限」，在系统弹出的页面里允许「忽略电池优化」。
2. 应用在**本次运行第一次真正出声**时也会主动提示授权，按提示走即可。
3. 授权成功后，该区块会显示「已加入白名单，后台播放不受系统限制」。没显示就回到系统设置里手动给 AuralFlow 加白名单（不同 ROM 的路径不同，通常在「电池」或「应用管理 → 后台管理」里）。

## 日志与报 issue

### 日志在哪

**桌面端（本版起）**：诊断日志会落盘到 Tauri 的应用日志目录，Windows 上是：

```text
%LOCALAPPDATA%\cn.chenle.auralflow\logs
```

目录里的当前日志文件是 `auralflow.log`（单个文件超过 2 MiB 就归档成带日期的文件，磁盘上最多保留 3 份）。取日志的方式：**设置 → 其他 → 「运行日志」→ 「打开日志目录」**，点一下就用资源管理器打开该目录，把文件直接拖进 issue。

> 日志落盘是**本版起**才有的能力：更早的版本没有这个目录，也没有「打开日志目录」这个按钮，界面上找不到就说明你的版本还是旧的，先升级再复现。

**移动端（本版起）**：诊断日志同样落盘，写在应用私有目录里，文件名形如 `app-YYYY-MM-DD.log`；Android 上的完整路径形如：

```text
/data/data/cn.chenle.auralflow.mobile/files/logs/app-2026-07-03.log
```

单个文件上限 1 MiB（超过就截断，只保留最近约 256 KiB），启动时自动清理 7 天前的日志。移动端没有「打开日志目录」这类系统能力，取日志只能靠路径：**设置 → 存储与数据 → 「运行日志」** 会显示日志目录路径与体积，点「清理日志」直接清空（不弹二次确认）；Android 上也可以用 `adb shell run-as cn.chenle.auralflow.mobile cat files/logs/app-2026-07-03.log` 把当天的日志取到电脑上（日期换成你要的那天）。

> 移动端日志落盘也是**本版起**才有的能力：更早的版本没有 `logs/` 目录，设置里也没有「运行日志」这一块，界面上找不到就说明你的版本还是旧的，先升级再复现。

### 提 issue 要带什么

提 issue 请带齐：

- **两端各自的应用版本号**（桌面端设置 → 关于；移动端设置 → 关于 → 当前版本）；
- **复现步骤**（做了什么、点了哪里）；
- **期望行为**（你以为会发生什么）；
- **日志**：桌面端按上面的路径取日志文件，直接拖进 issue；移动端按「运行日志」里显示的目录取当天的 `app-YYYY-MM-DD.log`，不方便取文件时把相关行复制进 issue（注意去掉账号、Cookie、WebDAV 密码等隐私信息）。

issue 入口：<https://github.com/0nini00/auralflow/issues/new/choose>
也可以直接走表单：[缺陷报告模板](../.github/ISSUE_TEMPLATE/bug_report.yml) / [功能建议模板](../.github/ISSUE_TEMPLATE/feature_request.yml)；表单已经把这些字段标成必填，照着填就不会漏。

## 已知限制

- Windows 安装包**未做代码签名**，SmartScreen 告警与部分杀软误报会持续存在。
- 桌面端更新**强制校验安装包签名**，不可关闭。
- 便携版**不带数据**：数据在系统用户目录的应用数据目录里。
- **自定义音源没有真正的沙箱隔离**，只导入可信来源的脚本。
- 内置网关**没有可配置项**，不能替换。
- 逐字歌词**只在歌词数据本身带逐字时间戳时**才有。
- 已下线来源（B 站）的历史条目在升级后自动丢弃，**不保留备份**。
- 移动端的 WebDAV 地址**只接受 `https://`**。
- 移动端日志写在**应用私有目录**（`logs/app-YYYY-MM-DD.log`，路径在「设置 → 存储与数据 → 运行日志」里显示）：没有系统级的「打开目录」入口，取文件得用文件管理器或 adb，应用内只能看路径与体积、并清空它们。
