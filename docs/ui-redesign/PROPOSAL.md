# AuralFlow 桌面端界面重设计 · 方案 v1

> 2026-10-21 · 基于实机运行截图（`desktop` Vite dev，1360×860 / 1460×980）+ 源码取证
> 配套高保真原型：[`mockup.html`](./mockup.html)（可切换 4 个页面 / 明暗主题 / 右栏）
> 本方案**尚未改动任何产品代码**，等你确认后再进入实施。

---

## 0. 一句话方向

把现在的「**一张大白卡里堆卡片**」改成「**一条连续的内容画布 + 一条真正干活的顶栏 + 一条全宽播放条**」：容器退后，封面和文字上前。

---

## 1. 现状审计（10 条，附证据）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **顶栏几乎不干活，却占了 86px** | `AppTitleBar` 34px（只有 logo + 窗口按钮）+ `Header` 52px（后退/前进/搜索/主题），两者合计占 1360×860 的 10% | 首屏少一行内容；顶部一条空白带 |
| 2 | **搜索框基本看不见** | `.af-header-search { background: var(--af-bg-surface) }` = `#f1f5ef`，落在 `--af-bg-base` `#eef2ed` 上，对比约 **1.03:1** | 用户找不到搜索入口；实际截图里只能靠 placeholder 辨认 |
| 3 | **三层卡片嵌套，没有层级差** | `.af-content`（白卡 + 16px 圆角 + `shadow-md`）→ hero 卡 → 错误条卡；`.af-main-container` 再套 16px padding | 页面像"卡片贴在卡片上"，视觉重心散 |
| 4 | **导航 11 项平铺，无分组** | `Sidebar.tsx` 的 `navItems` 一个数组到底：发现/搜索/排行榜/歌单广场/每日推荐/私人FM/云盘/我的歌单/下载/本地音乐/统计 | 发现类与曲库类混在一起，扫读成本高 |
| 5 | **搜索有三个入口** | 侧栏「搜索」+ 顶栏搜索框 + 首页 hero「搜索音乐」按钮 | 入口冗余，且侧栏搜索页本身没有空态 |
| 6 | **搜索页无查询时是纯空白** | 实机截图：只有输入框 + 分类 tab + 大片空白 | 新用户不知道能搜什么，也没有"最近搜索" |
| 7 | **播放条 105px 高，进度条横贯顶部** | `.af-player-bar { min-height: 84px }` + `.af-player-container { grid-template-rows: 18px auto }`，进度行独占一整行 | 进度与控制割裂；播放条比同类桌面播放器（Spotify 90 / Apple Music 74）更厚 |
| 8 | **字号阶梯有断层** | 12 / 13 / 14 / 16 / 18 / 24 / 32，缺 20 与 40；h1(32) 与 h2(24) 只差 8px | 「发现音乐」和「推荐歌单」几乎同级 |
| 9 | **空态/错误态是"一行灰字 + 裸文本重试"** | `.af-discover-notice` 一行 13px 次级文字，重试按钮是 `.af-btn-secondary` 内联 | 出错时页面像坏了，而不是"需要你做一个动作" |
| 10 | **组件没有沉淀** | 设置页有成熟的分段控件/色板/开关（`settings.css` 36KB），但其它页面各写一套；`components/` 下没有 `ui/` 原语层 | 同一控件在不同页面长得不一样，改一次要改多处 |

**做对的地方（必须保留）**：设置页的信息密度与控件完成度、歌单页的「eyebrow + 大标题 + 工具条」版式、歌曲表格的列语义、沉浸歌词的逐字卡拉 OK、封面取色氛围光、玻璃播放条。

## 2. 设计方向：Quiet Stage（静默舞台）

**判断**：音乐播放器的主角是封面、曲名和正在发生的事。容器的存在感越强，内容越弱。现在的问题是"每个区块都要有边框/底色/阴影"，于是没有任何一块显得重要。

三条原则：

1. **一层画布，只在真正浮起的东西上用阴影** —— 侧栏、内容、播放条共享同一底色体系，用**色调差 + 1px 细线**分层；阴影只留给播放条、菜单、弹层、右栏。
2. **一屏之内只有一个主行动** —— 每个页面只有一个绿色实心按钮（播放全部 / 搜索 / 创建歌单），其余全部降为描边或纯文字。
3. **每个空的地方都要给下一步** —— 空态、错误态、加载态统一成"图标 + 一句话 + 主行动"，不允许出现纯空白页面。

**品牌层与交互层分离**：品牌绿 `#3bd877` 保留在 logo、封面氛围光、播放态；**交互层用更深、更可读的绿**（light `#17a34a` / 文字 `#0c7a37`，对比约 5.4:1），解决现在"浅底上的强调色文字对比不足"的老问题（现 `--af-accent-strong` 用 `color-mix` 压深，仍不稳定）。

## 3. 信息架构

**导航从 11 项平铺 → 3 组 + 底部固定区**（搜索从导航移除，统一走顶栏 `Ctrl K`）：

```
发现            为你（登录后出现）      我的音乐
├ 首页          ├ 每日推荐             ├ 我的歌单   12
├ 排行榜        ├ 私人 FM              ├ 本地音乐  348
└ 歌单广场      └ 音乐云盘             ├ 下载
                                       └ 最近播放
─────────────────────────────────────────────
底部：听歌统计 · 设置 · 账号
```

**入口收敛**：
- 搜索：只保留顶栏（`Ctrl K` 聚焦），首页 hero 的「搜索音乐」按钮删除；
- 队列：从播放条弹层 → 右侧常驻面板（可收起），弹层只保留"更多操作"；
- 主题切换：顶栏保留图标，设置页保留完整三态。

**路由不变**：14 条路由与 URL 结构一律不动，避免破坏深链与历史记录。

## 4. 布局骨架

```
┌───────────────┬──────────────────────────────────────────┬─────────────┐
│  Sidebar 236  │  Topbar 56（含拖拽区 + 窗口按钮）           │             │
│               ├──────────────────────────────────────────┤ Now Playing │
│  发现          │                                          │   320       │
│  为你          │  Content（滚动，padding 26/32）            │  （可收起）  │
│  我的音乐      │                                          │             │
│               │                                          │             │
├───────────────┴──────────────────────────────────────────┴─────────────┤
│  Player 88（全宽，左 曲目 / 中 控制+进度 / 右 工具）                        │
└────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 尺寸 | 与现状的差异 |
|---|---|---|
| Sidebar | 236px（可拖 200–320，保留现有拖拽） | 分组 + 计数徽标；不再有独立 logo 大图块 |
| Topbar | 56px | **合并原 34px 标题栏**：logo 在左，面包屑居中偏左，搜索居中，右侧图标 + 窗口按钮。垂直 chrome 从 86 → 56px，**净赚 30px** |
| Content | `padding: 26px 32px 40px` | 去掉"白卡套白卡"，内容直接落在画布上 |
| Now Playing | 320px，可收起 | 新增。队列 + 当前封面 + 歌词预览，替代弹层 |
| Player | 88px，**全宽**（跨过侧栏） | 从"只在内容列内"改为"压住整个窗口底部"，建立稳定的基线；进度条回到控制组内 |

**为什么播放条要全宽**：现在播放条左右边界跟着内容列走，右栏一开就会被挤窄，且与侧栏底部错位。全宽后左侧封面与侧栏对齐、右侧工具与右栏对齐，是桌面播放器的通行做法（Spotify / Apple Music / YouTube Music 一致）。

**响应式收敛规则**（右栏展开时内容列只剩约 660px，必须提前定好）：

| 条件 | 规则 |
|---|---|
| 宽度 ≤ 1360 | 隐藏 hero 右侧封面（模糊封面仍在背景里），标题保持单行；卡片行 6 → 5 列 |
| 宽度 ≤ 1180 | 卡片 4 列，继续收听 2 列，榜单 2 列，hero 内边距收紧 |
| 高度 ≤ 820 | 侧栏导航项 38 → 32px、分组间距收紧；导航区可滚动（保留原生滚动，不加遮罩） |

> 实测教训：给滚动容器加 `mask-image` 做渐隐，会让 Chrome 把整块内容一起淡出（与相邻的 `backdrop-filter` 合成冲突），已弃用。

## 5. 设计令牌（替换 `theme.css`）

### 5.1 色彩

| 语义 | Light（新） | 现 Light | Dark（新） | 现 Dark |
|---|---|---|---|---|
| canvas 画布 | `#f3f3ef` | `#eef2ed` | `#080a09` | `#070c09` |
| surface 内容面 | `#fbfbf8` | `#f8faf6` | `#0d100e` | `#0c1310` |
| card 卡片 | `#ffffff` | `#ffffff` | `#141816` | `#121b16` |
| sunken 凹陷 | `#f0f0eb` | `#f1f5ef` | `#101312` | `#17221c` |
| line 描边 | `#e4e4dd` | `#d9e2da` | `#232925` | `#2a3a31` |
| ink 主文字 | `#15180f` | `#111a15` | `#eef2ee` | `#f1f7f3` |
| ink-2 次文字 | `#565d54` | `#46574d` | `#a3aea6` | `#c3d1c9` |
| ink-3 辅助 | `#8a9088` | `#5f7368` | `#6d786f` | `#93a89c` |
| **accent 交互** | `#17a34a` | `#3bd877` | `#3fd67e` | `#3bd877` |
| **accent-ink 文字** | `#0c7a37`（5.4:1） | `color-mix(58%)` | `#6fe6a1` | `#3bd877` |
| accent-soft 底 | `rgba(23,163,74,.10)` | `.10` | `rgba(63,214,126,.12)` | — |

**关键改动**：中性色从"绿灰纸面"改为"暖中性"——现在的 `#eef2ed` 带明显绿调，与强调色同色系，导致按钮和背景"融"在一起；改暖中性后绿色才跳得出来。同时 **`--af-accent-primary` 不再直接用于文字**，新增 `--af-accent-ink` 专供文字/图标，杜绝浅底对比不足。

### 5.2 排版

| Token | 值 | 用途 | 现状 |
|---|---|---|---|
| `--fs-display` | 38px / 1.1 / -0.03em | 详情页大标题 | 无（32 封顶） |
| `--fs-h1` | 30px / 1.15 / -0.025em | 页面标题 | 32 |
| `--fs-h2` | 19px / 1.3 | 区块标题 | 24 |
| `--fs-h3` | 15px / 1.35 | 卡片组标题 | 18 |
| `--fs-body` | 13px / 1.5 | 正文、列表 | 14 |
| `--fs-meta` | 12px / 1.4 | 元信息 | 13 |
| `--fs-caption` | 11px / 1.35 | 辅助、列头 | 12 |

字号整体下调 1px、h1/h2 拉开 11px 差：桌面信息密度高，14px 正文配 24px 区块标题会显得"标题很大、内容很小"。数字一律 `font-variant-numeric: tabular-nums`。

### 5.3 间距 / 圆角 / 阴影 / 动效

```
spacing: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40
radius:  6(标签) · 8(小控件) · 10(按钮/输入) · 14(卡片) · 20(面板/浮层) · 999(胶囊)
shadow:  e1 0 1px 2px rgba(20,25,15,.05)      ← 卡片静止
         e2 0 6px 18px -6px rgba(20,25,15,.14) ← hover / 播放条
         e3 0 22px 48px -16px rgba(20,25,15,.24) ← 弹层 / 详情封面
motion:  120ms(状态) · 200ms(位移/展开) · 300ms(页面进场)
         全部走 cubic-bezier(.4,0,.2,1)；prefers-reduced-motion 时归零（保留现有规则）
```

## 7. 关键页面改造

### 7.1 发现页
- Hero 从 168px 高的浅色块 → **272px 全宽沉浸式横幅**：封面模糊铺底 + 左→右暗化遮罩 + 34px 标题 + 主行动「播放全部」。
- 「推荐歌单」从等宽网格 → **6 列卡片行**（168px），hover 出播放按钮。
- 新增「继续收听」4 列小卡（44px 封面 + 断点位置），替代现在被撤掉的"最近播放"——它属于"回到刚才"，用**小卡**而不是整段区块，不抢首屏。
- 排行榜从"错误条"→ 3 张榜单卡（各带前 3 首），信息密度更高。

### 7.2 歌单详情
- 头部：196px 封面 + 38px 标题 + 描述 + 元信息 + **1 主 3 副**动作（播放全部 / 随机 / 下载 / 更多）。
- 表格：列头 11px 大写字距；行 52px；播放行有均衡器动画；操作列 hover 才出现，给标题列让出 56px。
- 滚动时头部动作条吸顶（新增，现在没有）。

### 7.3 搜索
- **补齐空态**：最近搜索 chips（可单条删除）+ 热门搜索（双列编号，前 3 名 accent 色）+ 按类别浏览 4 个磁贴。
- 搜索框唯一：进入页面时顶栏搜索框自动聚焦（原型里可以看到绿色 focus 环），页面不再放第二个输入框。

### 7.4 沉浸歌词
- 保留现有卡拉 OK 与封面呼吸，只调三处：背景模糊从 56px → 78px、亮度 .30（现在偏"泥"）；封面圆盘 + 细环替代绿色光晕；歌词列限宽 560px 并与封面作为整体居中。

## 8. 可用性与无障碍

| 项 | 做法 |
|---|---|
| 对比度 | 正文 ≥ 7:1，次级 ≥ 4.5:1，辅助文字 ≥ 3:1（仅用于元信息）；**强调色文字改用 `--accent-ink`** |
| 键盘 | 保留现有 `Space / ←→ / Shift+←→ / ↑↓ / M`；**新增** `Ctrl K`（聚焦搜索）、`Ctrl Q`（右栏开关）、`Esc`（关闭浮层/退出沉浸）；不与系统级快捷键冲突 |
| 焦点 | 统一 `:focus-visible` = 2px accent 外环 + 2px offset；列表行支持 `↑↓` 移动 |
| 命中区 | 桌面最小 28×28，主要操作 36×36；播放条控制 32×32 |
| 动效 | 全部 ≤ 300ms；`prefers-reduced-motion` 归零（沿用现有全局规则） |
| 滚动条 | 保留"必须成对声明"的硬规则（`scrollbar-width` + `scrollbar-color`） |

## 10. 风险与取舍

| 风险 | 说明 | 应对 |
|---|---|---|
| 合并标题栏 | Tauri 拖拽区与窗口按钮要重排，浏览器 dev 下需降级 | 先做一版保留 `startDragging` 逻辑，真机验证后再删旧标题栏；失败可一键回退（组件独立） |
| 令牌重写波及广 | `theme.css` 被所有 CSS 引用 | 只改值、不改名；分两次提交（先令牌、后布局），每次跑 `pnpm desktop:typecheck` + 目视回归 |
| 背景图 + 玻璃模式 | 新 token 会与 `.af-app-has-background` 的 rgba 规则冲突 | 玻璃规则改为引用新 token 的 `color-mix`，单独一屏验证 |
| 全宽播放条 | 侧栏不再贯穿到底，`af-resizing-sidebar` 的把手位置要调 | 把手改为侧栏内右缘（本来就要求），只调高度基准 |
| 视觉口味 | 深绿 accent 与现有荧光绿差别明显 | 见 §11 决策 2，可退回 B 方案 |

## 11. 决策状态

**已确认（2026-10-21）**
