# AuralFlow v0.7.2

上一版给本地曲补了「平台自动匹配封面」，那一档吃平台脸色——原唱被下架就匹配不到。本版补上**不依赖任何平台**的那一档：同目录的旁挂图片（`folder.jpg` / `cover.jpg` / 同名图片）。它就在你的硬盘上，换机器、断网都还在。

## 本地曲旁挂图片封面（桌面端）

- **顺序与移动端逐项一致**：内嵌封面 → 同目录旁挂图 → 无封面时才自动匹配平台。候选名同为 `folder.jpg` / `Folder.jpg` / `cover.jpg` / `Cover.jpg` / `folder.png` / `Folder.png` / `cover.png` / `Cover.png`，之后才试同名图 `<歌名>.jpg` / `.jpeg` / `.png`。同一份音乐目录在手机和桌面上会挑出同一张图。
- **不复制、不改写**：直接把用户那张图的路径交给界面引用。复制进封面缓存会让一张 12 首的专辑存 12 份同样的图，白占 512 MiB 的封面缓存；直接引用还能让你换掉 `folder.jpg` 后立刻生效，而且它不随缓存清理消失。
- **扫描只做目录项探测**：只看「文件在不在」，不读图片字节；`folder.jpg` 恰好是个目录时会跳过并继续试后面的候选名。同一目录十几首曲子只探一次。
- **单文件添加同样生效**：那条路径额外放行了该图片的读取权限（整目录扫描本来就已放行整个目录），否则界面会拿到空图。

## 桌面

- 版本同步到 0.7.2。
- 封面来源自此有四档，优先级固定：手动指定 → 内嵌 → 同目录旁挂 → 平台自动匹配。

## Android

- 版本同步到 0.7.2（versionCode 28）。**本版 Android 侧没有代码改动**，APK 重打只为版本号与 Release 一致：应用内更新拿 `releases/latest` 的 tag 与自身版本名比较，Release 比包内版本名高就会一直提示更新。

## 边界与未做

- **旁挂图被删除或改名后**：封面会显示为空图，要等下次扫描才更新（桌面端没有文件监听）。不会崩，也不会写坏曲库数据。
- **界面不区分封面来源**：内嵌、旁挂、平台自动匹配看起来一样，也没有「把这张图设为封面」的入口。
- **既没有内嵌封面、目录里也没有旁挂图、网易又搜不到时，仍然没有封面**：原唱已下架且没配图的曲目属于此类。封面暂时没有第二平台来源（QQ 音乐经网关搜索实测所有查询都返回 400）。
