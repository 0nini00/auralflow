# AuralFlow v1.0.2

这一版主要是修问题：移动端三处主流程缺陷（私人 FM 点歌、睡眠定时、稍后播放的随机索引），桌面端播放期的渲染开销，以及两端设计令牌终于收敛到同一份。桌面与 Android 同步到 1.0.2（Android versionCode **51**）。

## 移动端 · 修复

- 私人 FM「接下来播放」列表点了没反应：以前点第一行会变成暂停、点其他行什么都不做。现在点到哪首播哪首。
- 按歌数的睡眠定时到点不停播：以前只改界面状态、不停原生播放，15 秒静音占位轨走完会自己接下一首。现在到点真正暂停。
- 「稍后播放」插播时没有同步平移随机历史与已播集合，随机模式下会重播听过的歌、漏掉没听过的。
- 歌曲「更多」菜单里的「收藏到歌单 / 下载 / 其他版本」在 Android 上会点不穿（二级弹层与一级菜单同帧挂载），已按仓库既有的时序工具处理。
- 打开长歌单时「定位到当前播放曲」会少算一整个头部高度，现在等头部布局完成后再定位。
- 歌词平滑滚动从「10ms 步进自己补间」改成原生滚动动画，不再每 600ms 跨桥 60 次。
- 详情页吸顶头不再逐帧在 JS 线程写动画值，改为跨阈值触发一次原生动画。
- 设置里的滑块改用同步坐标，拖动不再回跳；可触控高度从 22px 提到 44px。

## 桌面端 · 性能与交互

- 播放进度锚点从每帧推送降到 4 次/秒（seek / 暂停 / 切歌仍立即刷新），播放条与沉浸页改用窄选择器订阅。
- 桌面歌词窗不再每帧重建整篇歌词：只有当前行更新进度，其余行保持稳定引用。
- 动态背景的配色观察器先比较封面色变量，不再每帧做一次 getComputedStyle。
- 鼠标拖尾特效在没有粒子时停止 rAF，不再空转清屏。
- 队列增删不再把「正在播放」面板弹回当前曲，用户翻到哪就停在哪。
- 歌曲菜单的每条关闭路径都把焦点还给触发按钮。
- 歌词窗 / 迷你窗按快照时间戳丢弃迟到消息，不再闪回上一首。

## 桌面端 · 后端

- 媒体缓存改为异步文件写入；容量清理移出 tokio worker，清理失败只告警不影响本次写入。
- 缓存删除现在会清掉同一 key 的所有扩展名文件，不会留下「已删但仍会命中」的残留。
- 清空资源缓存改为逐项 best-effort，正在写入的文件不会再让整次清理报错。
- 用户数据读取与 zlib 解压移出主线程。

## 设计系统

- 圆角、字号、间距刻度、品牌色与画布统一到 `@lx/core` 的同一份令牌；桌面 CSS 由契约测试逐值比对，改了一边忘另一边会直接测试失败。
- 两端默认强调色统一为 `#17a34a`（文字仍走更深的 `#0d7a42` 保证对比度），深色画布对齐为 `#0b0f0d`。
- 移除已无引用的 Drawer 依赖。
- 设计系统主文档从 2026-08 基线同步到现状。
