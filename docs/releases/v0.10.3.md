# AuralFlow v0.10.3

这一版没有新功能，是一次**以缺陷修复为主**的发布：把上一版之后一轮全仓审查翻出来的问题逐条修掉。其中第一条会直接影响你听到的音质，第二条会影响到「播放失败之后」的体验，都是能被感知到的问题，不是纯内部整理。桌面与 Android 同步到 0.10.3（Android versionCode **40**）。

## 修复 · 音质标签被静默当成 320k（影响可听音质）

这是本版最重要的修复，值得单独说明。

自定义 LX 音源脚本与第三方网关返回的音质标签并不统一：有的写 `flac`，有的写 `sq`，有的只写 `aac` 或 `opus`。旧实现遇到**不认识的标签**时，一律回落到 `320k`。当时的理由是「保证调用方永远拿到一个可用档位」，但它和播放解析的竞速逻辑撞在了一起：

竞速只在「**不低于**用户选定档位」的候选里挑最好的。于是当一个源实际只给 AAC、标签写成 `aac`，它会被当成 320k —— 比用户请求的 128k 还高，从而在竞速里**胜出**。结果是用户听到降级音频，界面上还显示着正常音质，没有任何线索。

现在的规则是：

- **认识的标签就采信**：别名表补齐了真实出现过的写法 —— `lossless` / `sq`（无损）、`hq`（320k）、`flac24` / `24bit` / `hi_res`（24bit）、`standard` / `std`（128k）等。
- **不认识的标签退回「本次请求的档位」**，不再凭空变成 320k —— 我们按这个档位去要的链，源又没给出可识别的信息，最合理的估计是它给了我们要的东西。
- 需要区分「这个源到底有没有自报音质」的地方，改用新增的 `classifyPlaybackQuality`，它会一并交出 `known`。

双端五处调用点（自定义源、隐藏兜底音源、官方网关）统一到同一份实现，避免出现「桌面能升到无损、移动端一直停在 320k」这类不对称行为。

## 修复 · 播放失败后声音仍停在上一首

整条解析链全部失败时，界面会切到新歌并显示报错，但引擎里装的还是上一首 —— 声音继续播旧歌、进度条冻住，而且引擎推来的状态会被当作「上一首的」丢弃，用户必须再切一次歌才能恢复一致。

现在失败收尾统一走一个函数：先解除目标登记、再停止引擎、最后写入错误状态。顺序是刻意的 —— 反过来 `stop()` 推出的 `idle` 会把刚写好的报错覆盖掉。

## 修复 · 桌面端渲染崩溃白屏

桌面端此前只有全局错误处理负责**记日志**：能留痕，但拦不住 React 渲染抛错后整屏变白。

新增的错误边界挂了三层，各自管住一块：

- **根级**按窗口角色隔离 —— 歌词窗崩掉不影响主窗口，反之亦然；
- **路由级**按路径隔离 —— 单个页面崩掉只废掉内容区，侧栏、顶栏、播放条照常可用，用户能切到别的页或继续听。切页会自动清掉错误状态，不用手动重试；
- **播放页**（NowPlayingPanel）独立包裹 —— 它自己在渲染期抛错不该带走播放条。

崩溃日志会带上 `componentStack`，这是排查白屏时唯一能定位到具体子树的线索。

## 工程化

- **桌面端接入 ESLint**。3.2 万行代码此前完全没有 lint。这次只开两条命中「运行时才会炸」的规则 —— `rules-of-hooks`（hook 数量不一致会让 React 直接抛错）与 `exhaustive-deps`（过期闭包表现为「切歌后还是旧歌的进度」）。不开风格规则是因为一次开满必然产生海量历史噪音，最后的结果一定是把规则关掉；先建立能常绿的门槛更可持续。
- **CI 新增 Android 构建任务**。原生层此前零 CI 覆盖，而「本地能跑、打包含才炸」的问题恰恰都在这儿：清单权限、Gradle 版本、RNTP 源码补丁在 CI 的 `node_modules` 布局下匹配不到。现在每次提交都会真正编译一次 arm64-v8a 并校验 APK 产出。
- **解析预算常量收敛到 core**。上一版把 2500ms / 10s / 1.6s / 并发 3 下沉到 `@lx/core`，但只接入了一半 —— 桌面端仍在手抄自己那份。这次全部改为从 core 导入，并把「8 源 × 4 档 = 30 请求」的实测依据迁进了 core 注释。

## 文档订正

- `outbound-host` 的头注释原先写着「两份实现必须手工同步，无自动化校验」。这是错的：实际有 49 条共享用例表（`outbound-host.cases.tsv`），JS 侧用 `fileURLToPath` 读它、Rust 侧用 `include_str!` 在编译期内联同一份文件，任一侧改了规则没同步，两边测试会同时红。现在注释改成契约说明，并写明分歧一律**对齐到更严的一侧** —— 历史上 7 处分歧全部是「JS 更严、Rust 更松」。
- 双端 SPEC / README / 特性对照表 / 验证基线按当前实现订正，清掉过期条目（含一处已不存在的二维码登录引用）。
- `PROJECT_OVERVIEW` 的全仓数字与测试计数按实测刷新。
