# AuralFlow v0.8.0

自 v0.7.10 以来的一次集中打磨，**只有桌面端改动**，Android 端未重建（仍在 v0.7.10）。主线是四件事：把界面基线收干净、修掉几个真实缺陷、让桌面歌词能滚、把播放条的三列关系理顺。

## 布局基线

- **修好一条早已失效的样式**：`index.css` 里 `.af-sidebar-resize-handle` 上方的花括号被写坏，整条拖拽把手的显示规则都没生效。修复后「悬停显示 2px 强调线」才真正生效。
- **横向留白只留一个来源**：视图内边距、内容滚动容器、内部区块三处各自加横向 padding，叠出一条宽窄不一的边。全部归零，只保留 `.af-content-scroll` 的 `32px`；12 个位置在 1360 / 980 / 900 三档窗口实测左右边距差 Δ=0。
- **z-index 收敛成表**：原来散着 18 处裸数值，重写为 13 档真实层级（topbar 20 / inline-popover 50 / menu 100 / player 1000 / player-backdrop 1199 / player-overlay 1200 / modal-backdrop 1300 / tooltip 1600 / immersive 1800 / pact 3000 / portal-backdrop 9998 / cursor 9999），13 处改引用后实测计算值全部不变。
- **删掉误导性的间距令牌**：`--af-spacing-*` 六个令牌实测 **0 引用**（全仓 727 处间距全是内联 px），保留只会让人以为间距受统一约束。改为注释记录 2px 网格约定。

## 详情页与歌曲行

- 歌单 / 专辑 / 歌手 / 历史四个详情页**删掉返回键**：顶栏已有前进后退，页内再放一个既是重复入口，也把标题挤到第二行。
- 详情页 header 改用 **container query**（780 / 620 两级）而不是媒体查询——右栏一开容器就变窄，窗口宽度根本感知不到。
- 封面与文字的纵向对齐从 `flex-end` 改为 `flex-start`：原来封面比文字块矮时，差额 109px 全堆在封面上方。
- **六个歌曲列表页的操作列**：播放键换成「下一首播放」（行点击本来就负责「从这首开始播」，播放键是重复的）；删掉「...」菜单，其中唯一有价值的「移除」提为可见按钮。

## 菜单与提示：两个同类缺陷

- **歌单卡片的「...」菜单**：菜单是滚动容器内的绝对定位元素，最后一行卡片的下拉被 `overflow` 裁掉 89px、又被播放条盖住；而且它没有任何关闭生命周期，点空白、Esc、滚动都不会关。改为 portal 到 body + `fixed` 定位 + 下方放不下时向上翻，并补上空白 / Esc / 滚动三条关闭路径。
- **导入导出的「已取消」提示常驻**：取消分支把「什么都没发生」写成一条消息，而这一行没有自动清理机制。改为取消一律清空（歌单页 3 处 + 设置页自定义音源 1 处）。

## 每日推荐

- 日期原来是原生 `<select>`，**展开的列表由系统绘制**，深色玻璃界面里弹出一块系统默认样式的列表。换成自绘下拉：限高 320px、超出内部滚动、Esc / 点空白 / 滚动都能关，选中项带勾选。
- 触发器所在位置是**固定深色渐变**的封面头部（`#14181a → #121615`，与主题无关），而控件用的是主题色变量——浅色主题下就成了「深底上放一个白底控件 + 深灰标签」。改为按深色底配色，数值与头部已有的次级按钮覆盖完全一致。
- 顺手补了「返回今日」按钮：它不在 `.af-playlist-actions` 里，吃不到那条已有覆盖，之前是同一行里两种配色。
- **下拉菜单是全站唯一没有细滚动条的可滚区域**（实测默认滚动条占 15px），统一到全站的 `thin` + 主题色（实测 10px）。

## 侧边栏收起

- 右边缘新增收起/展开按钮，样式直接复用右栏「正在播放」同一颗图标按钮（30×30 + 16px 图标）。
- 收起后保留 36px 窄带：按钮是唯一的展开入口，`aside` 真的收成 0 就再也点不回来。
- 状态落盘到设置（新增 `sidebarCollapsed`，`patch_settings` 会拒绝未知键，所以 Rust 侧同步加了字段）。实测展开 236px / 收起 36px，内容区宽度 +200px。

## 桌面歌词

- **数据模型换了**：原来是「当前行 + 后续最多 4 行」，无论窗口多高都看不到刚唱过的那句。改为「整篇歌词 + 当前索引」，并补上 `previous` 角色。
- **窗口改为整篇滚动**，当前行滚到固定行位（`currentRow = floor((可见行数-1)/2)`）。2 行窗口行为与旧版完全一致（当前行 + 下一行），**3 行起才有上一行**，因此默认行数从 2 改为 3。
- **窗口高度跟着内容走**：量一行的真实高度，按「可见行数 × 行高 + 行距 + 工具栏」算出目标高度，经新命令 `set_lyric_window_height` 下发（宽度保持用户当前值）。同时把恢复尺寸的上限从 120 提到 560——原来 120 会把多行窗口在下次打开时压回去。

## 播放条

- 删掉右列最右那颗「整页歌词」按钮：它与「点封面」是同一个动作（`setImmersiveLyricsOpen(true)`），同一功能两个入口，其中一个是孤悬在最右的 40px 图标。
- 右列图标间距 2px → 8px，音量组两侧 12px（靠留白分组，不加分隔线）。
- 三列比例 `1fr / 1.5fr / 1fr` → `0.9fr / 1.5fr / 0.9fr`，进度条上限 520 → 620px：实测进度条轨道 432 → **497.5**。
- 曲目信息不再拉伸（`flex: 1 1 auto` → `0 1 auto`），「添加到我的喜欢」回归文字侧，不再随窗口宽度飘到列的最右端。

## 其它

- 三处空 `catch` 补日志（`playerSync` 的 BroadcastChannel、`DeepLinkHandler`、`desktopLyricToggle` 两处）。
- `components` / `services` / `views` 三个 README 对齐真实行数、目录与路由。
- 新增 `desktop-lyric-lines`、`frontend-daily-date-picker` 两个测试文件；歌单菜单用例适配 portal。全套 **60 文件 / 484 例**通过。

## 已知未做

- 播放条激活态（歌词开 / 定时开 / 队列开 / 非顺序播放）现在只靠图标变强调色，比原来的底色弱。要更强可以加底部指示条。
- 桌面歌词窗口高度「自动优先」：改字号/行数/译文会把高度改回公式值，手动拖的高度会被覆盖。
- 首尾歌词行不会真正居中（没有加首尾 spacer），锚点在两端会被夹住。
- 播放条改动无像素级截图：没有当前歌曲时播放条根本不渲染，几何数据是用打包后的真实 CSS 复刻同款 DOM 实测的。

## 升级

桌面端直接覆盖安装即可，设置与缓存都不受影响。Android 端本版没有更新，仍用 v0.7.10 的包。
