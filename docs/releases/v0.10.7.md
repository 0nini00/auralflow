# AuralFlow v0.10.7

这一版只做一件事：**音乐云盘里的歌终于有歌词了**，桌面与 Android 同步（Android versionCode **44**）。

## 为什么云盘曲一直没有歌词

两个原因叠在一起，缺一个都解释不了用户看到的现象（网易云客户端有词，我们这边没有）：

**1. 云盘条目的 id 不是线上曲目 id。** 云盘的每个条目有自己的一条「云盘条目 id」，歌词接口对它只回占位词：

```json
{ "lrc": { "lyric": "[00:00.00]暂无歌词" }, "uncollected": true }
```

歌词本身挂在**线上曲目那条记录**上。我们把这个占位词收敛成「没有歌词」之后就结束了，从没去线上找过对应的歌。

**2. 这个「没有歌词」被持久化缓存冻了 7 天。** `暂无歌词` 属于可缓存空结果（本来是为了避免反复请求），于是第一次失败就把结论写进缓存，重开应用也只是读回它——所以是「一直没词」，而不是「偶尔没词」。

## 修复

- **桌面**（`wyProvider.getLyric`）：占位词且 `wyCloud === true` 时，用「歌名 + 歌手」走带 Cookie 的 `cloudsearch` 找到线上曲目，再取它的歌词。只有云盘曲走这一层——普通在线曲拿不到词就是真的没有。
- **移动**（`musicApi.fetchWyOfficialLyric`）：同一条路径。此前移动端拿到占位词后回退内置网关，而云盘条目在网关里也查不到词，结果一样是空。
- **匹配必须严格**：`cloudsearch` 对这类关键词会把翻唱排在官方曲前面（实测未登录搜「雨下一整晚 周杰伦」，前 5 条全是翻唱）。贴错歌词比没歌词更糟，所以判定收敛到 `@lx/core` 的 `pickSameSongCandidate`（内部即 `isSameSong`）——规整歌名相等 + 至少一位歌手重合 + 双方都有时长时差 ≤ 5 秒；歌名规整后为空不做匹配。两端共用同一份判定，不再各写一套。
- **不再把云盘的空结果落盘**：这类空结果只留内存，一次失败不会变成 7 天的结论。`CACHE_VERSION` 2 → 3，把已经冻结的旧结论清掉（播放地址缓存一并重置，代价只是首次播放重新解析一次直链）。

## 验证

- 桌面 dev 实机（`debug.log` + 缓存文件）三首云盘曲命中并落盘：
  - 雨下一整晚：云盘 2117337923 → 线上 2160518331（256s vs 255s），36 行，含「作词: 方文山 / 作曲: 周杰伦」与正文；
  - 惊叹号：1932243439 → 25638798（231s vs 231s），39 行；
  - 疗伤烧肉粽：1925751838 → 2158507830（186s vs 191s，差 5s 恰在容差内）命中。
- 新增 `desktop/tests/wy-cloud-lyric.test.ts`（4 例）把 eapi 的 fetch 换成假响应，锁定四件事：占位词 → 搜索 → 取线上曲目歌词、翻唱排前面也不误选、匹配无果返回空（绝不把占位词当歌词）、普通在线曲不触发搜索。
- core 293（+4，含 `pickSameSongCandidate` 的「翻唱不误选」）/ 桌面 565（+4）/ 移动 572 / Rust 74 全通过；三端 typecheck 通过、双端 lint 0 错误。
- 移动端行为无法在本机真机跑，靠移动端全量套件、typecheck 与共用的 core 判定覆盖；真机表现以本版 APK 为准。
