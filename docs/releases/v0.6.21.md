# AuralFlow v0.6.21 — Windows

本次为歌词链路修复的第二阶段:对照 lx-music-desktop 的网易云歌词实现,用真实接口数据
复验后补齐 v0.6.19 修复的三处残留问题。

## 修复

- **逐字歌词(yrc)歌曲的头部元信息不再整批重复**(此前「制作人 / 吉他 / 混音」等行会出现两次)。
  根因:桌面端把 lrc 逐行合并进 yrc 主轨,按「同文本 ±1200ms」去重;而真实接口里 yrc 的
  富文本元信息行**全部落在 t=0**,lrc 的同批行时间却随行递增(0/463/926/1389ms…),第 4 行起
  漂移超出容差被判为不同行,于是整批重复(实测孤勇者 67→78 行)。现对齐 lx-music-desktop
  的语义:**yrc 解析非空即整轨独占采用**,lrc 不再参与合并;yrc 解析不出任何行时才整轨退回 lrc。
- **升级后播过的歌重新拉取完整歌词**(此前旧缓存会把修复整个遮蔽)。
  根因:歌词解析结果缓存没有版本概念,旧版本写入的残缺词条要活 30 天——即使升级到
  v0.6.19,播过的歌仍命中旧词,表现为「修了但看不到」。现在持久化缓存整体升版失效
  (播放直链缓存一并重置,代价只是首次播放重新解析一次直链),localStorage 歌词缓存
  同步换前缀,旧词条不再命中。
- **逐字歌词的翻译 / 罗马音改用对齐音轨**。此前主轨选 yrc 时,翻译仍用 lrc 对齐的
  `tlyric`、罗马音优先 `romalrc`,与逐字轨时间轴存在错位;现按 lx 的分工优先使用与
  逐字轨对齐的 `ytlrc` / `yromalrc`,缺失时再退回 lrc 对齐轨。

## 验证

- 用真实 eapi 接口数据(孤勇者 / 爱人错过 / 晴天 / Lemon)复验:双端解析结果与单轨参照
  三方一致,孤勇者 78→67 行、元信息 10 行无重复。
- 共享核心 146(新增 1)、桌面前端 453(新增 5)、移动端 594 项测试通过;三处类型检查通过。

## 下载与更新

- `AuralFlow-v0.6.21-windows-x64-setup.exe`:NSIS 安装版(支持应用内自动更新)。
- `AuralFlow-v0.6.21-windows-x64-portable.exe`:便携版。
- 从 v0.6.19 及更早版本升级:安装版可直接用「设置 → 检查更新」,或下载 setup.exe 覆盖安装;
  便携版请直接替换可执行文件。
