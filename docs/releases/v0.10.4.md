# AuralFlow v0.10.4

这一版是**缺陷修复**，三件事都来自实际使用中能被直接看到的问题：桌面端右键永远是浏览器菜单、双端「下一首播放」点了在队列里看不到、铺上壁纸后设置页是一块块黑方块。桌面与 Android 同步到 0.10.4（Android versionCode **41**）。

## 修复 · 「下一首播放」看不见、随机播放下不生效（双端）

点「下一首播放」之后，队列面板里看不到刚点的那首；要等自动切歌播到它，它才突然出现在队列里。随机播放时更奇怪——插进去的歌要等随机抽到才播，等于没生效。

根因是两端对这件事的实现**语义不同**：

- 移动端把它写进独立的「稍后播放」暂存区 `tempPlayList`，而队列面板只渲染主队列，所以当场看不到；
- 桌面端确实是立即插进主队列，但 `next()` 在随机模式下是现场抽号、在 FM 模式下是去拉推荐，两条路径都不看插入位置。

现在统一成：**立即插入主队列当前曲之后**，队列面板当场可见。同时新增一个「播锚点」`pinnedNextSong`——只记曲目身份（按下标记会随队列增删漂移），`next()` 先消费它，因此随机播放与私人 FM 里也保证刚插的歌下一个播。

两个容易漏的细节一并处理：

- 插入点之后的所有下标整体 `+1`，`shuffleHistory` / `playedIndices` 同步平移。否则「上一首」会回到错曲、随机去重也会错位。
- 空队列时插入即开播，且此时不留锚点——留了会让下一次「下一首」把同一首再播一遍。

移动端歌单页的批量「设为稍后播放」入口保持原行为不变。

## 修复 · 桌面端右键总是浏览器菜单

桌面端此前没有任何 `contextmenu` 处理，因此**任意位置**右键弹出的都是 WebView 自带菜单（返回 / 刷新 / 另存为 / 检查），而这些动作在应用里没有意义。

现在在入口处注册一次全局拦截，把它们全部压掉；同时**保留可编辑控件的默认菜单**（输入框、文本域、`contenteditable`），否则右键粘贴也会一起没了。

> 这是「屏蔽」而不是「自建菜单」。组件里自己写的右键菜单不受影响——事件在冒泡到 `window` 之前就被组件处理了。

## 修复 · 设置壁纸后设置页是一块块黑方块

设置页的卡片与控件直接用 `--af-bg-surface` / `--af-bg-elevated` 这两个**实色** token（深色主题下是 `#101312` / `#141816`），而壁纸模式原有的半透明覆盖只针对 `sidebar` / `content` / `card` 等具体元素，既没改 token、也没覆盖设置页的类。于是首页是毛玻璃、设置页却是一块块近乎纯黑的面板。

现在在壁纸模式的作用域内改写表面色 token（浅色 / 深色两套，乘以你设置的蒙层强度），一次覆盖所有页面的卡片、输入框与分段控件；已单独调过的元素（侧栏、内容区、首页卡片、统计卡片）规则更具体，不受影响。另外补了两处 token 做不到的事：

- 顶栏并入侧栏那组半透明规则（它原本是实色 `--af-bg-page`）；
- 设置页卡片与标签栏补 `backdrop-filter`，标签栏原本是 `color-mix(bg-page 92%)`，深色下等同于一条实心黑带。

透出背景后，三级文字（提示、单位、占位）会糊进壁纸里，因此这一档在壁纸模式下提亮/压深一档，而不是靠加厚遮罩把背景盖掉。

> 深浅由 **设置 → 外观 → 背景蒙层浓度** 控制。调低壁纸更明显，调到 0 面板会完全透明，文字可读性会明显下降。
