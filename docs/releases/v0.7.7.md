# AuralFlow v0.7.7

这一版新增**网易云音乐云盘**：桌面端与 Android 端都能浏览你自己上传到网易云的文件并播放。它是一个登录后才解锁的功能——云盘里的文件只对账号本人可见，未登录时入口不渲染、也不发任何请求。

## 云盘为什么单独做一条取链

云盘曲复用在线曲那套数字 id 与同一个播放地址接口（`/song/enhance/player/url/v1`），但**取链语义与在线曲完全不同**，三处差异决定了实现方式：

- **不做转码**：请求哪一档 `level`，返回的都是上传文件原样。实测三份上传全部请求 `exhigh`，拿到的 `level` 分别是 `standard`（128 kbps mp3）、`lossless`（944 kbps flac）、`hires`（2987 kbps flac）。因此「选 320k 省流量」在云盘曲上不成立。
- **不在任何第三方源里**：网关因缺 `gateway` 元数据必然失败，自定义源脚本只会白跑一轮（最多 1600ms 交错展开 + 10s 阶段预算）。两端都改为对云盘曲**直接走带 Cookie 的官方直连**，跳过整个竞速编排。
- **不参与跨源替代**：QQ 侧的同名曲是另一份录音，替过去等于播错歌；未匹配到在线曲目的上传（本机账号实测 121/161，占 75%）靠歌名匹配尤其不可靠。两端解析失败一律如实报错，不再静默换歌。

## 修掉的三个连带缺陷

实现过程中撞到并修掉了三处会让它「看起来能播、其实播错」的问题：

- **试听误判**：`isPreviewStream` 用「请求档位的标称码率」估算流时长，而云盘返回的是原文件码率。128k / 3.4MB / 223s 的上传在无损档会被估算成 32 秒、低于 60 秒阈值，判成 30s 试听片段后整档作废并报出误导性的「解析到试听片段(约 32s)」。云盘曲现在跳过这一层判定（解析期、磁盘缓存、下载三处都跳）。
- **免登录 eapi 兜底**：两端 wy 直连原本在 weapi 失败后回退到不带 Cookie 的 eapi。对 `matched` 的上传（占 25%），同一个 id 在线上也有一份录音，eapi 可能返回**线上版本而不是用户上传的那份**——听起来能播，实际是另一份音频。云盘曲已关闭这条回退。
- **占位歌词阻断匹配**：未匹配条目的歌词接口返回 `[00:00.00]暂无歌词` + `uncollected: true`。原逻辑判定成「已有歌词」，既不显示真歌词、也不再走 LRCLIB / 平台搜索的自动匹配链。两端已改为把占位歌词当无歌词处理——这一条对所有无歌词的网易云歌曲都生效，不只云盘曲。

## 其余实现细节

- 云盘列表走 weapi `/v1/cloud/get`，条目经 `@lx/core` 的 `toCloudMusicInfo(s)` 统一映射成带 `wyCloud` 标记的 `MusicInfo`，两端共用同一份映射，避免字段路径（`songId` / `simpleSong.id`、`dt` 毫秒、`al.picUrl`）各写一份后漂移。
- 分页游标按**接口原始条数**推进，而不是映射后的条数：映射会丢掉缺 id / 缺歌名的记录，用映射后长度会让下一页起点往前挪、条目重复，且总数仍按原始条数计，「加载更多」永远停不下来。
- 切账号 / 退出登录以请求世代丢弃晚到的旧响应，避免上一个账号的云盘被写回列表。移动端此前还不会在账号变化时重载，且刷新失败会清空已加载的列表，一并对齐。
- 列表行显示的是**文件真实码率**（`无损` / `Hi-Res` / `320k`），不是用户选的档位。缓存标签仍按请求档位走，否则持久化缓存的降级链查询永远命不中、每播一次就要重新解析。

- `pnpm check:all` 退出码 0：`@lx/core` / 桌面 / 移动三端 `tsc` 与移动端 eslint 全过。
- 单测：`@lx/core` 203 例（新增云盘映射 10 例：id / 歌名 / 时长毫秒转秒 / 封面来源 / 多歌手拼接 / 丢弃不可取链条目）、桌面 65 文件 531 例、移动端 617 例，全通过。
- 真实接口 + 真实账号 Cookie 实测：云盘 161 首、容量 4.9 GB / 64 GB；`/v1/cloud/get` 一页 50 条经 `toCloudMusicInfos` **50/50 映射成功**，id / 歌名 / 时长 / 封面 / 歌手零缺失，`dt=229067ms → 229s` 换算一致；三个样本文档（128k mp3、944k flac、2987k flac）取链全部返回可用 URL，Range 探活均拿到总字节数。

## 边界与未做

- **只做了浏览与播放**：上传、删除、云盘内搜索都未做。云盘本身也不支持「搜索云盘」——只有被网易云匹配到在线曲目的上传才能被 `cloudsearch` 命中，仅自己可见的条目搜不到自己。
- **仍无真机人工验收**：验证到自动化测试与打包为止。装好后建议实测三条：Cookie 过期时点云盘曲应当报错而不是换歌；移动端点云盘曲的下载；把默认音质改成无损后播低码率上传（验证试听误判已消除）。
- 云盘曲会按普通网易云歌曲进磁盘缓存（桌面 2 GiB / 移动 2 GB 的 LRU），会自然淘汰；但一首 80 MB 的 hires 上传仍会占满相当一部分缓存。
- 「加入网易云自建歌单」对云盘曲仍然可见。对未匹配的上传，服务端是否接受这些 id 尚未验证——需要向账号发写请求才能确认，因此没有在发布前测。
