# AuralFlow v0.7.9（仅桌面端）

这一版只改桌面端的主窗口尺寸策略。**Android 端代码未改动**，仍是 0.7.8（versionCode 34），本轮没有重建 APK。

## 问题

窗口尺寸会被持久化并在启动时恢复。用户把窗口拖大/拖小之后，那个大小就被一直带下去；界面上没有任何「还原」入口，只能自己再拖回来——拖不准就再也回不到设计尺寸。

## 改成什么

**尺寸归应用管，位置归用户管。**

- 设计尺寸定为 **1360×860**。依据是布局断点在 980 / 920 / 900 / 768：1360 宽能完整放下「侧边栏 + 多列内容区」，860 高在 1080p 屏幕上还给任务栏与播放条留出余量。
- **每次启动都按这个尺寸打开**，不管上次被拉成什么样。
- 小屏上自动收一收：按「显示器尺寸扣 48/80 余量」收窄，且不低于最小尺寸 900×600，不会顶到任务栏或超出屏幕。
- 位置仍然沿用上次的（窗口还在某块屏幕内时）；副屏被拔掉则回退居中。这是原有行为，没有改。
- **不再恢复最大化状态**：用户要的是「每次以设计尺寸打开」，恢复最大化与此冲突。

## 实现

- 新增 `resolve_startup_geometry`：它的签名里没有「保存的尺寸」这两个参数，从类型上堵死旧尺寸回流的路；越界收窄、最小尺寸抬升、居中兜底继续复用原有的 `resolve_main_window_geometry`。
- 落盘只写位置，不再写尺寸与最大化；设置文件里残留的旧值不再被读取。
- `tauri.conf.json` 的 `width`/`height` 同步改为 1360/860，与代码里的常量保持逐字一致。

## 验证

- `cargo check` 无告警。
- `window_state` 模块 17 例通过，其中新增 4 例：设计尺寸恒定（位置沿用、尺寸不沿用）、1280×720 小屏收窄、800×500 极窄屏不低于最小尺寸、位置不可达时居中且尺寸仍为设计值。
- Rust 全套 78 例通过（`pnpm test:rust`）。

## 边界

- 装好后第一次启动即可看到效果：窗口回到 1360×860。之后运行期间仍然可以自由拖拽（这是正常的窗口行为），只是**下次启动会回到设计尺寸**。
- 若你的屏幕远大于 1080p、希望默认更大一些，改 `DEFAULT_WIDTH`/`DEFAULT_HEIGHT`（以及 `tauri.conf.json` 的 width/height）即可，两处必须一起改。
