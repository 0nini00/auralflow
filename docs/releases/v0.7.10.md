# AuralFlow v0.7.10

自 v0.7.8 以来攒了 13 个提交，一次发完。**桌面端与 Android 端都重建了**（v0.7.9 那次是只改窗口尺寸的桌面-only 包，且没有发布，从 v0.7.8 直接升到本版即可）。

这一版的主线只有三条：桌面端视觉语言重做、补上排行榜与歌单广场、把「本地歌曲联网匹配歌词」整条链路删掉。云盘列表反复请求的问题也在这一版收口。

## 桌面端：设计语言 v2（结构不动，重新定视觉）

用户的原话是「前端设计有点难看」。先做量化审计（对比度 / 尺度离散度 / 装饰用量），再按「先修可读性、再去装饰」动手，**布局结构一处未改**。

- **可读性**：`--af-text-tertiary` 在白底实测只有 **2.56:1**，而它有 **49 处**在写时长、歌手、说明文字——这是「灰蒙蒙」的主因。抬到 `#64748b`（白底 4.76、页面底 4.51）；深色侧 `#64748b`(3.50) → `#8b95a5`(5.51)。`--af-text-quaternary` 原本 1.48，连当装饰都吃力，降级为纯装饰灰；排行榜序号是正文，改回 tertiary。
- **圆角**：散着 18 种字面量，收敛到 4 / 8 / 12 / 16 / 999 五档（改 47 处，每处偏移 ≤2px）。原来 56px 高的顶栏做成 20px 胶囊，是「卡片套卡片」观感的主因。
- **阴影**：侧边栏、顶栏、内容面板、播放条一律去掉 `box-shadow`——它们与邻居之间已有 16px 画布间距 + 1px 描边，阴影是纯装饰的第三层。阴影令牌改成只服务浮层（菜单 / 弹窗 / 拖拽层）。
- **模糊**：播放条去掉 `backdrop-filter: blur(20px)`——`bg-elevated` 不透明，模糊不产生任何视觉效果，只有合成开销。
- **字号**：组件里 18 种字面量归入 token 的 7 级（改 101 处）。11 与 12、13 与 14 并排出现时读起来不是「有层次」而是「没对齐」。剩下 7 个不同取值都是 `clamp()` 流体标题与图标尺寸，本就该如此。
- **间距**：首页与歌单列表对齐 4px 网格。

## 桌面端：排行榜 + 歌单广场（新页面）

- **排行榜** `/charts`：28 个榜分 4 组——官方榜 4、特色榜 10、场景榜 8、语言榜 6，卡片带封面与更新频率。
- **歌单广场** `/playlist-square`：16 个分类 chip + 热门/最新排序，触底自动加载，请求失败有重试。
- **发现页改版**：去掉「最近播放」，换成「推荐歌单」+「排行榜试读」（取官方榜前 10）。
- 推荐与榜单走一个**不带 cookie 的公开接口服务**，与账号级 weapi 分开，10 分钟 TTL；接口挂了退回内置榜单列表并给出提示，不会留白页。
- 榜单分组表与分类表放进 `@lx/core`（`sources/leaderboard.ts`），移动端改为从这里 re-export——两端共用一张表，不会各改各的。

## 桌面端：侧边栏与窗口

- 侧边栏支持拖拽调宽（200–360px），松手落盘；240px 下「我的歌单」不折行。
- 「歌单」改名为「我的歌单」，与新的「歌单广场」区分（页面标题本来就是「我的歌单」）。
- 主窗口每次以设计尺寸 **1360×860** 打开，只沿用上次的位置（细节见 v0.7.9）。

## 双端（破坏性）：本地歌曲不再联网匹配歌词

**这是删功能，不是加功能。** 之前本地曲可以「搜索匹配歌词」：LRCLIB + 平台检索 + 内容指纹 + 候选选择 + 孤儿表。整条链路删除，本次提交 **−7470 行**。

现在本地曲歌词只有三个来源：内嵌标签、同目录旁挂 `.lrc`、在「编辑元数据」里手写的按曲文本。`localLyrics` 写空字符串 = **显式清空**，不会再回落到文件里的词。

理由：匹配链路上每一环都要维护（指纹算错、候选选错、平台改接口），而**错配的歌词比没有歌词更糟**——用户会以为这首歌的词就是这样。封面匹配早前已按同一逻辑删掉，这次把最后一半补齐。

## 双端：云盘列表不再反复请求

分三层修，最后一层是本版新加的：

1. **页内复用**：同一账号加载过就复用，只有点「刷新」或换账号才重拉。
2. **跨页面**：切走再回来不再请求。
3. **落盘缓存**：按 `accountUid` 分区写盘，10 分钟保鲜。
   - 保鲜期内冷启动**零请求**，`loading` 直接是 `false`（所以不再有那圈转）。
   - 已过期则先把旧列表显示出来、同时后台刷新——旧数据比空白有用，「打开就转圈」的根因是空白而不是请求慢。
   - 退出登录删掉该账号那份；空列表不落盘；用户点「刷新」跳过缓存。
   - 桌面写 `library/cloudDrive.json`，为此在 Rust 的命名空间白名单 `ALLOWED_NAMESPACES` 里加了 `cloudDrive`（不加会被直接拒）；**不进 WebDAV 同步**——它是缓存不是用户数据。
   - 移动写 AsyncStorage `auralflow.mobile.cloudDrive.v1:<uid>`。
   - 桌面最多保留最近 3 个账号。

## 桌面端：迷你播放器封面的黑框

从封面进入全屏播放页、退出后封面外面会多一圈黑边。原因是 `useDialogFocus` 关闭时把焦点还给封面那个 `div[role=button]`，Chromium 给 `:focus-visible` 套了 `outline: auto 1px`（深色），而外层 wrapper 圆角是 0、里面图标圆角是 12px，方框就露出来了。按用户要求「键盘退出也不该有任何装饰」处理成 `outline: none`：**焦点仍然还回去**（Tab 位置不变），代价是这块没有可见焦点指示，已写进代码注释。

## 边界与未做

- **本地歌曲没有任何联网补救**：文件里没有歌词就是没有歌词，界面上也不再有「去搜索」的入口。这是刻意的。
- **榜单试读缺失**：`/api/toplist` 目前不返回曲目，卡片只能进详情页；映射代码留着，接口恢复返回 `tracks` 就生效。
- **云盘仍是只读浏览器 + 播放**：上传、删除、云盘内搜索未做；「加入网易云自建歌单」对云盘曲的服务端行为依旧未验证（需要向账号发写请求）。
- 云盘缓存只存列表与容量，不含取链与播放权限；云盘里新上传的文件要等保鲜期过或手动刷新才出现。
- 设置 / 本地音乐 / 搜索 / 统计几页的间距节奏还没按 4px 网格统一；`--af-border-focus` 的对比度（约 1.3:1）低于 WCAG 对焦点指示的 3:1，单列一项待做。
- 仍**没有真机人工验收**：验证到自动化测试与打包为止。
