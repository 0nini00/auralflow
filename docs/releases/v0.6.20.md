# AuralFlow v0.6.20 — Android

本次为**移动端伴生发布**,功能与桌面端 v0.6.19 无差异,目的是让「最新版本」同时带上
Android 安装包(桌面版发布后,Latest 会只剩 Windows 安装包,移动端通道会失效)。

## 说明

- 移动端与桌面端共用同一套核心歌词解析,桌面 v0.6.19 修复的「歌词缺作词/作曲/编曲」
  来自 `@lx/core`,因此手机端同样受益。
- 本次移动端自身没有行为改动,仅为重新打包并让更新通道同时覆盖两端。

## 看不到的改动(发布脚本加固)

- `apps/mobile/build-release-arm64.ps1` 改为**按 ABI 文件名精确取包**(`app-<abi>-release.apk`,
  优先取 `apk-alt` 稳定路径),不再按 `LastWriteTime` 取「最新」——四个 ABI 分包时间戳相同,
  旧写法会取到别的架构。
- 构建前清空 `outputs/apk/release` 与 `outputs/apk-alt`,避免混入上一次构建的产物。
- 本次实测确认了另一个坑:每次构建会**重写全部四个 ABI 分包**,后一次构建会把前一个
  架构的 APK 覆盖成不完整的原生库(实测 arm64 的 `.so` 从 21 个掉到 17 个)。因此必须
  「构建一个架构 → 立刻复制保存 → 再构建下一个」。本次两个包的 `.so` 均为完整的 21 个。

## 下载与更新

- `AuralFlow-v0.6.20-arm64-v8a.apk`:主流 64 位机型(推荐)。
- `AuralFlow-v0.6.20-armeabi-v7a.apk`:较老 32 位机型。
- 两个包均使用与以往相同的正式签名(SHA-256 证书指纹一致),可直接覆盖安装。

## 验证边界

- 共享核心 145 项、桌面前端 448 项、移动端 594 项测试通过;三处类型检查通过。
- 两个 APK 均校验:`versionName=0.6.20`、`versionCode=20`、`lib/*` 原生库各 21 项、
  `apksigner verify` 通过且证书指纹与上一版一致。
- **仍需你实测确认**:手机端覆盖安装后能否正常启动与播放(功能未改动,预期无变化)。
