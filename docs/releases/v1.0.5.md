# AuralFlow v1.0.5

这一版是性能与稳定性：桌面和 Android 两端都针对卡顿、切歌等待、长列表滚动做了结构性修复；播放取链恢复严格并发上限、切歌真正取消旧请求，并补上跨源回退与候选可用性校验。桌面与 Android 同步到 1.0.5（Android versionCode **54**）。

## 播放（双端共用）

- 取链恢复严格并发：慢音源、多音质不再突破并发上限；切歌会取消上一首仍在途的解析，桌面端取消一路传到 Rust 网络层。
- 共享预读按消费者管理：同一首邻曲只解析一次；前台拿到地址或取链失败后都不再等歌词，最后一个消费者退出才取消共享请求。
- 候选校验：自定义音源候选先探测可用性再返回，避免把不可播地址交给播放器；播放预览仍保持保守识别。
- QQ 音乐元数据补全改为独立 4 秒期限的共享请求，取消播放只取消当前消费者的等待。
- 跨源回退：一个源失败后按优先级继续找可用地址，失败会报出真实原因。

## 桌面端 · 性能

- 歌词滚动逐帧插值只更新当前行，300 行歌词不再每帧重绘整篇。
- 短句歌词不再被反复延后的 600ms 滚动等待卡住；跨行与 seek 立即定位，手动拖动后的恢复语义保留。
- 搜索结果四个分类改为虚拟列表，无关分类回包不再重建全部歌曲与行内组件。
- 下载页虚拟化；进度只写内存，阶段变化才落盘，不再每次进度都序列化全部历史记录。
- 收听统计按月增量持久化（`listeningStats/YYYY-MM.json`），统计页差量聚合；旧历史在迁移全部落盘后才删除。
- 首页各分区独立发布：榜单就绪即显示并开始试读，不再被最慢的推荐请求挡住。

## 移动端 · 性能

- 搜索改用共享分组索引与稳定引用：3000 首不同名歌曲分组从 900 万次 normalize 降到 9000 次（Node 约 5385ms → 13ms）。
- MP3 下载后的标签写入移到 Android 原生后台线程，不再把整首音频读成 Base64 在 JS 里转换（10MiB 约 978ms、427MiB 堆增量）。
- 搜索、下载、歌单列表虚拟化，封面只走原生图片缓存，失败才查离线文件。
- 歌词滚动只更新相邻行并复用节点；进度条去掉逐帧 JS 监听，连续拖动不再抢 JS 线程。
- 云歌单缓存按歌单增量写入；自动同步保留本地编辑，显式下载可覆盖。
- 本地扫描复用目录签名，导入与授权写标签都走后台。

## 其它

- 桌面端新增队列编辑、音量、播放请求代次等模块的拆分（延续 1.0.4 的重构路线）。
- 下载完整性检查覆盖缓存下来的 URL，识别到预览片段时拒绝写入。

## 验证

core 456 项、桌面 869 项、移动端 1073 项、Rust 111 项测试全部通过（Rust 以 `--locked` 运行）；双端 TypeScript 检查与 lint 通过；Android ARM64 release 构建与正式签名校验通过；桌面生产构建通过。

性能数字来自受控计数与组件/原生逻辑验证，不是真机帧率或 CPU 实测；没有连接设备时未做真机 FPS 测量。
