# AuralFlow v0.10.9

一次以「看得清、关得掉、对得上」为主的版本：移动端把设计令牌、弹层遮罩与文字对比度收敛到同一套事实，桌面端把沉浸页浮层拉回与其它弹窗一致的观感，双端补齐 WebDAV 历史同步的可见性，并修掉一条让发布门禁偶发变红的未捕获异常。桌面与 Android 同步到 0.10.9（Android versionCode **46**）。

## 样式 · 移动端设计令牌收敛

`spacing` 原来只有 4 的倍数，而代码里真实高频值是 **2 / 6 / 10 / 14 / 18**（全仓 335 处裸值里这五个占 155 处）——它们无处可去，只能继续硬编码。现在把半步纳入刻度（`line / tight / snug / cozy / roomy`），旧的 `xxs/xs/s/m/l/xl` 全部保留，避免一次性改动 556 处引用。

`theme/tokens.ts` 里并行的第二套图标规格 `iconButton { sm, md, lg, xl }`（36/44/56/64）与 `controlTokens` 的 `control.iconButton`（36/44/56）只差一档却都在被引用，最终只有一处真正生效。删掉前者，只留 `controlTokens` 一个来源，hitSlop 统一走 `controlHitSlop()`。

## 可读性 · 对比度按实测值改，不按感觉改

| 令牌 | 变化 | 实测 |
|---|---|---|
| `textSubtle`（浅色） | `#8b918a` → `#646863` | 2.90:1 → **5.67:1**（surface）/ 4.74:1（surfaceMuted） |
| `textSubtle`（深色） | `#6e7c77` → `#79837b` | 4.42:1 → 达标 |
| `dangerInk` | 新增（浅 `#ba3535` / 深 `#f05353`） | 给「危险」文字用的可读档，不再拿填充色当文字色 |

强调色上的文字色原来按「感知亮度 > 0.58 取深色」判断，这个阈值对中明度色失真：`#4a90d9` / `#8e7cc3` / `#22a06b` / `#d9534f` 都被判成「该配白字」，实测对比度只有 3.33–3.96:1。改成与 `buildPrimaryInk` / `buildActionFill` 同一做法——直接比较两种候选色的真实对比度取高的那个。

## 弹层 · 遮罩与底色只有一个来源

新增 `apps/mobile/src/theme/sheetTokens.ts`：遮罩 `rgba(0,0,0,0.45)`、顶部圆角 20、拉手尺寸与底部最小内边距。8 个底部弹层（动作菜单、加入本地歌单、下载音质、播放队列、版本选择、评论、更多、播放设置）全部接入；另外 10 处写死遮罩的文件（`0.45 / 0.5 / 0.6 / 0.62` 四种取值）统一到 `sheet.scrim`。

`BottomSheet` 的面板底色从 `palette.background`（**页面**底色）改成 `palette.surface`（卡片表面）——深色主题下前者比后者更黑，弹层看起来像「另一个应用的窗口」。这正是竖屏播放器里那几个弹窗底色不一致的来源。

新增 `apps/mobile/src/utils/modalSequence.ts`：Android 上两个 Modal 串联时，`onDismiss` 与「上层关闭」抢同一帧，点空白关不掉下层。

## 提示 · 失败要自己开口

- 双端新增 `components/ui/Toast.tsx`（桌面另有 `styles/toast.css`）。
- **WebDAV 启动自动同步失败**过去在两端都无可见反馈：桌面只写日志，移动端只往 store 里塞 `message`（WebDAV 页面没打开就看不到），用户看到的只有「等了几秒，云端没变化」。现在两端各弹一次错误提示（移动端每次启动最多一次，避免离线时反复骚扰）。

## 修复 · WebDAV 播放历史静默失败（双端不相通的根因）

移动端 `historyStore.mergeHistory` 是 `catch {}`。后果不止「没合并」：同步流程会认为下载成功，接着**把未合并的本地历史当全集上传**，把云端来自另一台设备的记录整份覆盖——两端于是永远各自为政，而且无日志、无提示。

现在合并失败会记 `logger.warn` 并**抛出**，同步停在上传之前；其余三处历史写入的 `catch {}` 也补了日志（保持不打断播放）。同时补上此前完全缺失的跨端用例：用桌面端 `buildPlayHistorySync` 的条目形状喂给移动端 `autoSyncPlaylistsOnce`，断言条目落地、真实时间不被改写、上传原样带回。测试桩的 AsyncStorage 之前缺 `multiSet / multiGet / multiRemove`，导致历史落盘在用例里一直静默失败——这条路径等于从没被覆盖过。

## 桌面端 · 沉浸页与设置页

- 「播放队列 / 更多 / 歌词设置」浮层原来叠了一层暗场玻璃，与 `.af-dropdown-menu`、对话框的实心 elevation 底不是一套。现在统一 `--af-bg-elevated` + 主题描边 + `--af-shadow-lg`，文字用 `--af-popover-ink` 快照（沉浸页把 `--af-text-*` 改写成浅色，浮层跟着用就会浅底浅字）。
- 「更多 → 收藏 / 加入歌单」点空白关不掉：菜单 portal 到 body，全屏遮罩是普通 `div`，mousedown 经 React 树冒泡到沉浸页根节点去调 `startDragging()`——系统级窗口拖动吃掉后续鼠标消息，`click` 永远不来。现在拖拽白名单排除 `.af-add-menu*`，并让一次点空白连带收起「更多」面板。
- 设置 → 数据管理：两张缓存卡改用与「播放历史」同一套 `SettingRow` 节奏（标题 + 说明 + 右侧操作），统计数据作为第二行用发丝线分隔。此前说明文字被 `max-width: 62ch` 压成左上一小块，卡片又没有外边距，看着又挤又散。
- 下载页空状态改用新的 `empty-state.css`。

## 修复 · 发布门禁偶发红灯

`playerStore.ts` 的音量持久化定时器直接 `patchSettings(...).catch(...)`。测试桩返回 `undefined` 时，`.catch` 在定时器里抛未捕获 `TypeError`，vitest 判为 unhandled error → 进程退出码 1（用例本身全绿）。v0.10.6–v0.10.8 的发布说明里都把它记为「已知无关问题」。现在用 `Promise.resolve(...)` 归一化，连续两次 `vitest run` 均为 0 退出码。
