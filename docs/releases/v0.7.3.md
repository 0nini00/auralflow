# AuralFlow v0.7.3

修一个会让移动端**整屏崩溃**的问题：播放带来源标注的本地曲时，界面报「应用遇到了一点问题」。

## 修了什么

- **现象**：Android 端播放本地曲时整屏崩在错误边界上，提示 `Maximum update depth exceeded`。多发于歌词来自 LRCLIB、或命中同曲异唱的曲子——共同点是那首歌的歌词**带来源标注**。
- **根因**：v0.7.1 引入的「来源标注出现一次就退场」里，取标注的那个选择器每次调用都返回**新建的对象**，而 Zustand 5 的 `useStore` 内部就是 `useSyncExternalStore`、**没有相等比较**——React 认为它读到的快照一直在变，于是无限重渲染，直到自己抛错。此前标注常驻、选择器返回的是 store 里已有的来源对象，引用稳定，所以没有这个问题。
- **修法**：按来源对象的身份缓存标注对象——同一份匹配期间永远返回同一个引用，换一份匹配（新的来源对象）自然得到新对象，没有可标注的来源时稳定返回 `undefined`。
- **顺带修掉一个同源缺陷**：修复前，播放器每秒的进度推送都会重建标注并把退场计时器一直重置，标注实际上永远不会自己消失。
- 排查了移动端**所有** store 订阅点：只有这一处选择器返回新对象，其余都是字段取值、数组元素或函数引用（引用稳定）。这条规则已写进 `apps/mobile/SPEC.md`，避免同类写法再现。

## 桌面

- 版本同步到 0.7.3。**桌面端没有这个缺陷**（那边的标注是渲染时算出来直接交给 hook 的，不进 store 选择器），本版桌面端没有代码改动。

## Android

- 版本同步到 0.7.3（versionCode 29），含上述修复。
- 如果仍有「应用遇到了一点问题」，先点「重试」；反复出现请按 `docs/FAQ.md` 的要求带上日志提 issue。

## 测试与验证

- 新增回归用例（`tests/local-media-lyric-origin.test.cjs`）：同一来源跨 state 对象必须返回同一个引用、换来源必须换对象、无来源稳定 `undefined`。已验证该用例在旧实现下**失败**（`AssertionError: Values have same structure but are not reference-equal`）、修复后通过。
- 移动端：615 例全过（614 + 1）。双端类型检查、`@lx/core` 类型检查与移动端 lint 通过，`pnpm check:all` 退出 0。
- 发布后复验：7 个资产齐全、`releases/latest` 返回 v0.7.3、两份更新清单与两条 update endpoint 均为 v0.7.3、线上 arm64 包与本地校验过的包逐字节一致且 21 个原生库齐全、两个 APK 的 `versionCode=29 / versionName=0.7.3` 由 `aapt` 核对。

## 下载与更新

- `AuralFlow-v0.7.3-windows-x64-setup.exe`：NSIS 安装版（支持应用内自动更新）。
- `AuralFlow-v0.7.3-windows-x64-portable.exe`：便携版。
- `AuralFlow-v0.7.3-arm64-v8a.apk` / `AuralFlow-v0.7.3-armeabi-v7a.apk`：Android 正式签名包。
- 从 v0.7.1 / v0.7.2 升级：桌面端「设置 → 检查更新」；Android 端在「设置 → 关于」里检查更新，或直接下载 APK 覆盖安装。

## 边界与未做

- 本版只修崩溃，不改标注的展示行为（同曲异唱停 10 秒、出处停 4 秒后自动退场）。
- **仍未做真机人工验收**：验证到自动化测试与打包为止。装好后建议按 `docs/mobile-verification-baseline.md` 走一遍本地曲播放（尤其是歌词来自 LRCLIB 的曲子）确认不再崩。
