# AuralFlow v0.7.8

这一版修 v0.7.7 云盘的两处实测问题，并精简移动端首页入口。

## 云盘加载不全（两端）

两个独立原因，都修了：

- **每页只取 50 条**：进页面只看到头 50 首，必须手点「加载更多」才往下走。实测接口对 `limit=200` 的请求会**一次返回整个云盘**（本机账号 161 首一次到位），所以默认页大小改成 200；是否还有下一页改用接口自带的 `hasMore` 判定（实测只有最后一页为 `false`），比用「已加载条数 < 总数」推算可靠。
- **移动端列表被套在 ScrollView 里**：`SongList` 的 `virtualized` 路径本身就是 FlatList 滚动容器，之前又套了一层 `ScreenScrollView`，内层拿不到滚动、`onEndReached` 永远不触发，于是只能看到首屏那一批。改为 `SongList` 直接作为滚动容器，头部内容走 `ListHeaderComponent`、空态与「加载更多」走 `ListFooterComponent`、翻页走 `onEndReached`——与歌单详情页、我喜欢页同一套写法。

顺带补的两处：

- 桌面端加触底自动加载（`IntersectionObserver`，400px 预取），库比 200 首更大时也不必反复点按钮。
- 追加分页按 `source:id` 去重：翻页期间账号里增删条目会让 offset 错位，不去重会出现两条一模一样的行、React key 也会撞。

## 移动端首页入口精简

快捷入口原来是 7 个（搜索 / 播放历史 / 每日推荐 / 私人 FM / 音乐云盘 / 排行榜 / 歌单广场），过密。去掉「搜索」——底部标签栏本来就是搜索页，首页再放一个是重复入口。剩下 6 个。

## 验证

- `pnpm check:all` 退出码 0：`@lx/core` / 桌面 / 移动三端 `tsc` 与移动端 eslint 全过。
- 移动端 617 例、桌面 65 文件 531 例全通过。
- 接口分页实测：`limit=200` 一次返回 161 条且 `hasMore=false`；逐页 `offset` 递增到 161 时返回 0 条、`hasMore=false`，累计唯一 `songId` = 161，无重复。

## 桌面

- 云盘默认一次加载整个库；超大库触底自动续拉。
- 版本同步到 0.7.8。

## Android

- 云盘页改用虚拟化列表（`SongList virtualized`）：长列表只渲染可视区、滚动跟手，触底自动续拉。
- 首页快捷入口去掉「搜索」。
- 版本同步到 0.7.8（versionCode 34）。

## 下载与更新

- `AuralFlow-v0.7.8-windows-x64-setup.exe`：NSIS 安装版（支持应用内自动更新）。
- `AuralFlow-v0.7.8-windows-x64-portable.exe`：便携版。
- `AuralFlow-v0.7.8-arm64-v8a.apk` / `AuralFlow-v0.7.8-armeabi-v7a.apk`：Android 正式签名包。
- 从 v0.7.7 升级：桌面端「设置 → 检查更新」；Android 端在「设置 → 关于」里检查更新，或直接下载 APK 覆盖安装。

## 边界与未做

- 仍是**只读浏览 + 播放**：上传、删除、云盘内搜索未做（云盘本身也不支持搜索自己未匹配到在线曲目的上传）。
- **仍无真机人工验收**：验证到自动化测试与打包为止。
- 「加入网易云自建歌单」对云盘曲仍然可见，服务端是否接受未匹配上传的 id 仍未验证——需要向账号发写请求才能确认，没有在发布前测。
