# AuralFlow v0.10.6

这一版做了一件**方向上的修正**，外加一串使用中被指出的细节缺陷。桌面与 Android 同步到 0.10.6（Android versionCode **43**）。

## 推荐歌单：换数据源，而不是自己造轮换

v0.10.5 试过用「候选池 + 本地按日洗牌 + 换一批」让推荐歌单每天不同。回退之后查清了更根本的问题：**我们一直在用错接口**。

两端此前请求的是 `playlist/list?cat=全部&order=hot`——那是**歌单广场的运营热度榜**（分页列表），几天都不动，所以怎么刷新都一样。网易云 App 首页那块「推荐歌单」用的是 `weapi/personalized/playlist`：服务端按账号画像给一批，**没有 offset**，按天更新。

现在：

- **桌面**：新增 `getPersonalizedPlaylists`（weapi），首页优先用它；拿不到再回退公开列表。
- **移动**：新增 `fetchWyPersonalizedPlaylistMix`（复用已有 weapi 通道），回退链为「个性化歌单 → 每日推荐歌单 → 公开列表」。
- **不再有本地洗牌**：每天不一样由服务端负责，客户端不重复实现一遍。

## 修复 · 打开应用要点一次「重试」推荐歌单才出来

日志里抓到两行，对应两个独立原因：

```
[discover] 个性化失败：未设置网易云 Cookie
[discover] 公开兜底返回 0 条
```

1. **冷启动时序**：`weapiCall` 读的是模块级 cookie，只由登录流程或 `getWyCookie()` 填充。首屏在账号检查之前调个性化接口，必然因「未设置网易云 Cookie」失败。修复：调用前先主动读一次 settings。
2. **兜底本身是空的**：实测公开 `/api/playlist/list` **不支持 `order=new`**——同参数下 `order=hot` 返回 12 条，`order=new` 的响应体里没有 `playlists` 字段。所以一旦回退就是 0 条。修复：两端兜底改成「先试 new，拿不到退回 hot」。

## 修复 · 壁纸模式下的几处「黑块」

不是漏改一个 token 那么简单，三处成因不同：

- **主推卡片与歌单详情头部**：本身是「封面打底 + 深色蒙层」的固定深色设计（`#101513`、`#14181a → #121615`，蒙层 0.9）。壁纸模式下改成半透明底 + 更薄的蒙层 + 打底封面提亮。专辑、艺人、每日推荐复用同一个头部类，一处修改覆盖四处。
- **「保存到」条与选中态按钮**：根因是**自定义属性在声明处就冻结**——`--af-bg-secondary: var(--af-bg-surface)`、`--af-button-active-bg: var(--af-button-secondary-bg)` 定义在 `html` 上，只改底层的 `--af-bg-surface` 不会影响这些别名。已在壁纸作用域内重新声明这些别名；选中态改成强调色淡填充。
- **顶栏前进/后退外面多一个方框**：`.af-topbar-nav` 只是两个图标按钮的内联容器，却被并进了「顶栏/侧栏」那组半透明规则（带描边与大阴影）。已从该组移除。

## 样式 · 主播放键改用强调色

`.af-play-button` 原本是「反相文字色」：深色主题白底、浅色主题近黑——那个最该被一眼找到的按钮看起来像没上色。改为强调色填充 + `--af-text-on-accent` 图标，hover 用 `--af-accent-hover`。

## 关于 v0.10.5 的回退

v0.10.5 的「候选池 + 每天一版 + 换一批」已整体回退（两个 `git revert` 提交），相关模块与 UI 入口均不存在。回退原因是**方向错了**：该功能试图在客户端模拟服务端本就有的每日更新。回退后的版本号越过 0.10.5 继续向前，因此本版为 0.10.6。
